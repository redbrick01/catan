# 구현 계획서: 2단계 턴과 개발 카드 제한 정교화

작성일: 2026-05-26

## 1. 작업 목적

`docs/reference/rule-gap-analysis.md`의 2단계 항목을 구현한다. 주사위 전후 행동 가능 타이밍을 명확히 제한하고, 개발 카드 사용 제한과 새로 산 개발 카드 판정을 실제 규칙에 가깝게 개선한다.

## 3. 현재 구현 상태

현재 프로젝트는 개발 카드 구매와 기사 카드 사용을 지원한다. 개발 카드는 문자열 배열로 저장되며, `player.newDev`에 같은 문자열을 넣어 이번 턴 구매 여부를 판정한다.

현재 문제:

- 건설, 교환, 개발 카드 구매 함수가 주사위 전에도 실행될 수 있다.
- 버튼 비활성화는 일부 있으나 함수 내부 방어가 부족하다.
- 한 턴에 개발 카드 1장만 사용할 수 있다는 제한이 없다.
- 개발 카드가 문자열로만 저장되어 같은 종류의 오래된 카드와 새 카드를 정확히 구분하기 어렵다.
- `game.winner`가 `0`일 때 falsy로 처리될 수 있는 조건이 일부 있다.

## 4. 구현 범위

- 건설, 교환, 개발 카드 구매의 주사위 이후 제한
- 도둑 처리, 카드 버리기, 약탈 대상 선택 중 행동 차단
- 한 턴에 개발 카드 1장 사용 제한 추가
- 개발 카드 데이터 구조를 객체 기반으로 개선
- 새로 산 개발 카드 판정을 `boughtTurn`으로 개선
- 기사 카드 사용 로직을 새 데이터 구조에 맞게 수정
- 승점 계산에서 카드 객체를 반영
- UI의 개발 카드 개수 표시를 새 구조에 맞게 유지

## 5. 구현하지 않을 범위

- 도로 건설 카드 구현
- 풍년 카드 구현
- 독점 카드 구현
- 승점 카드 비공개 UI 개선
- 플레이어 간 교역
- 항구 교역
- 은행 재고 시스템

## 6. 수정 대상

- `script.js`
- 필요 시 `index.html`, `styles.css`

이번 단계는 주로 `script.js` 수정으로 처리한다.

## 7. 데이터 구조 변경

기존:

```js
player.dev = ["knight", "victory"];
player.newDev = ["knight"];
```

변경:

```js
player.dev = [
  {
    id: "dev-1",
    type: "knight",
    boughtTurn: 3
  }
];
```

게임 상태에 다음 값을 추가한다.

```js
devCardSeq: 0,
usedDevThisTurn: false
```

## 8. 구현 순서

1. `game` 상태에 `devCardSeq`, `usedDevThisTurn` 추가
2. `freshPlayer()`에서 `newDev` 제거
3. 개발 카드 객체 생성 함수 추가
4. `buyDevCard()`를 객체 기반으로 변경
5. `playKnight()`를 객체 기반으로 변경
6. `endTurn()`에서 `usedDevThisTurn` 초기화
7. `visiblePoints()`에서 승점 카드 객체 반영
8. 건설, 교환, 개발 카드 구매 함수 내부에 행동 가능 조건 추가
9. 버튼 비활성화 조건 보완
10. 새 게임 시작 시 개발 카드 상태 초기화

## 9. 검증 방법 초안

- `node --check script.js`
- 개발 카드 구매 시 객체가 생성되는지 확인
- 이번 턴 구매한 기사 카드는 사용 불가인지 확인
- 이전 턴 구매한 기사 카드는 사용 가능인지 확인
- 한 턴에 기사 카드를 2장 사용할 수 없는지 확인
- 주사위 전 건설, 교환, 개발 카드 구매가 함수 내부에서 차단되는지 확인
- 주사위 후 건설, 교환, 개발 카드 구매가 가능한지 확인

## 10. 위험 요소

- 기존 `player.dev.length` UI는 유지되어야 한다.
- 승점 카드 계산이 깨지면 승리 판정에 영향이 있다.
- 기사 카드 사용 후 배열에서 제거하면 개발 카드 개수 표시가 줄어드는 기존 동작은 유지된다.
- 다음 단계에서 다른 개발 카드를 구현할 때 이번 구조가 확장 가능해야 한다.

## 11. 롤백 방법

문제가 발생하면 `script.js`의 개발 카드 구조 변경과 행동 제한 변경을 이전 상태로 되돌린다. 문서 산출물은 기록으로 유지할 수 있다.
