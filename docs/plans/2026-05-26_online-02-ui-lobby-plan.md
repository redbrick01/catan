# 온라인 02 UI/대기실 구현 계획

## 목표

친구들이 헷갈리지 않고 온라인 방을 만들고 참가할 수 있는 UI를 만든다. 이 단계의 핵심은 예쁜 화면보다 상태를 분명히 보여주는 것이다.

## 범위

포함:

```text
온라인/오프라인 모드 선택
닉네임 입력
방 만들기
공유 URL 표시
복사 버튼
방 참가
대기실 참가자 목록
방장 표시
연결 상태 표시
접속 실패/참가 실패 안내
게임 시작 버튼
```

제외:

```text
계정 로그인
방 목록 검색
관전
채팅
방장 이전
고급 설정 화면
```

## 화면 상태

클라이언트는 다음 화면 상태를 가진다.

```text
modeSelect
offlineSetup
onlineNameInput
onlineLobby
game
connectionLost
```

## 시작 화면

기존 setup 화면을 바로 게임 설정으로 쓰지 않고, 먼저 모드 선택을 보여준다.

```text
Catan

[오프라인 게임]
[온라인 방 만들기]
[온라인 방 참가하기]
```

동작:

```text
오프라인 게임 -> 기존 플레이어 수/이름 입력 화면
온라인 방 만들기 -> 닉네임 입력 후 createRoom
온라인 방 참가하기 -> 방 코드/URL 입력 또는 ?room= 자동 인식
```

## URL room 파라미터 처리

친구가 공유 URL로 들어오면 `?room=abc123`를 읽는다.

```text
http://192.168.0.12:4173/?room=abc123
```

처리:

```text
room 파라미터 있음 -> 온라인 참가 흐름
room 파라미터 없음 -> 모드 선택 화면
```

## 닉네임 입력

방 만들기:

```text
온라인 방 만들기
닉네임: [민수]
[방 만들기]
```

방 참가:

```text
방 코드: abc123
닉네임: [지훈]
[참가하기]
```

검증:

```text
빈 이름 불가
너무 긴 이름 제한
공백만 있는 이름 불가
```

개인용이므로 중복 이름은 허용해도 된다. 다만 UI에서 `나` 표시가 있어야 한다.

## 대기실 화면

방장 화면:

```text
온라인 대기실

방 코드: abc123
공유 URL:
http://192.168.0.12:4173/?room=abc123
[복사]

참가자 3/4
- 민수  방장  나  연결됨
- 지훈        연결됨
- 수아        연결됨

[게임 시작]
```

Network URL 후보가 여러 개 있으면 방장이 선택할 수 있게 한다.

```text
공유할 주소 선택
( ) http://192.168.0.12:4173/?room=abc123
( ) http://10.0.0.5:4173/?room=abc123
```

이유:

```text
VPN, 가상 어댑터, 여러 네트워크 카드가 있으면 서버가 고른 IP가 친구들에게 맞지 않을 수 있다.
```

참가자 화면:

```text
온라인 대기실

방 코드: abc123
방장이 게임을 시작할 때까지 기다리는 중

참가자 3/4
- 민수  방장  연결됨
- 지훈        나  연결됨
- 수아        연결됨
```

## 게임 시작 버튼

활성 조건:

```text
내가 방장
방 status가 lobby
참가자 3~4명
모든 참가자가 connected
```

비활성일 때 짧은 이유를 보여준다.

예:

```text
3명 이상 모이면 시작할 수 있습니다.
연결이 끊긴 플레이어가 있습니다.
```

## 연결 상태 표시

상단 또는 대기실에 연결 상태를 표시한다.

```text
연결됨
재연결 중
연결 끊김
서버 응답 대기 중
```

게임 중에도 보여줘야 한다.

예:

```text
내 상태: 지훈으로 접속 중
연결: 정상
현재 차례: 민수
대기: 민수의 행동을 기다리는 중
```

## 접속 실패 UI

친구들이 가장 자주 만날 수 있는 문제를 짧고 구체적으로 보여준다.

상황:

```text
방을 찾을 수 없음
방이 가득 참
이미 게임이 시작됨
서버 연결 실패
잘못된 방 코드
재접속 토큰이 맞지 않음
```

권장 문구:

```text
방을 찾을 수 없습니다. 공유받은 URL이 맞는지 확인하세요.
방이 가득 찼습니다. Catan은 3~4명까지 참가할 수 있습니다.
이미 시작된 게임입니다. 이번 방에는 새로 참가할 수 없습니다.
서버에 연결할 수 없습니다. 같은 와이파이인지, 방장이 서버를 켜 두었는지 확인하세요.
```

LAN 접속 실패 안내에는 다음 체크리스트를 함께 보여줘도 좋다.

```text
같은 와이파이/LAN인가요?
URL이 127.0.0.1이 아니라 방장 PC의 IP인가요?
방장 PC의 서버가 아직 켜져 있나요?
Windows 방화벽이 차단하고 있지 않나요?
```

## 공유 URL 복사

복사 버튼은 `navigator.clipboard.writeText()`를 사용한다.

성공:

```text
복사되었습니다.
```

실패:

```text
복사에 실패했습니다. URL을 직접 선택해서 복사하세요.
```

대기실은 휴대폰에서도 깨지지 않아야 한다. 게임 화면 전체 모바일 최적화는 후순위여도, 친구가 휴대폰으로 URL을 열어 참가할 가능성이 높기 때문이다.

최소 기준:

```text
공유 URL이 화면 밖으로 넘치지 않음
복사 버튼이 터치 가능
닉네임 입력과 참가 버튼이 모바일 너비에서 겹치지 않음
참가자 목록이 좁은 화면에서도 읽힘
```

## 오프라인 모드 보호

기존 오프라인 모드는 최대한 건드리지 않는다.

원칙:

```text
오프라인 선택 전까지 기존 startGame()을 호출하지 않음
오프라인 선택 후에는 기존 흐름과 동일하게 동작
온라인 상태 변수는 오프라인 게임에 영향을 주지 않음
```

## 온라인 세션 상태

클라이언트에 다음 상태를 둔다.

```js
const onlineSession = {
  enabled: false,
  roomId: null,
  playerId: null,
  playerToken: null,
  seatIndex: null,
  isHost: false,
  connected: false,
  pendingRequestIds: new Set()
};
```

## 완료 기준

```text
첫 화면에서 오프라인/온라인 선택 가능
공유 URL로 들어오면 자동으로 참가 화면 표시
방장이 공유 URL을 복사할 수 있음
접속 실패/참가 실패 이유가 사용자에게 표시됨
대기실 참가자 목록이 실시간으로 갱신됨
방장에게만 게임 시작 버튼이 보이거나 활성화됨
대기실이 모바일 너비에서도 깨지지 않음
오프라인 게임은 기존처럼 시작됨
```

## 수동 테스트

```text
1. 첫 화면에서 오프라인 게임 시작
2. 기존 게임이 정상 동작하는지 확인
3. 새로고침 후 온라인 방 만들기
4. 공유 URL 복사
5. 시크릿 창에서 공유 URL 접속
6. 닉네임 입력 후 참가
7. 대기실 양쪽 목록 비교
8. 참가자 수가 부족할 때 시작 버튼 비활성 확인
```
## 2026-05-26 작업 전 갱신

이번 작업은 온라인 모드 2단계 UI 대기실까지만 구현한다.

변경 대상:

```text
index.html
script.js
styles.css
docs/plans/2026-05-26_online-02-ui-lobby-plan.md
```

구현 범위:

```text
첫 화면에 오프라인/온라인 방 만들기/온라인 방 참가 선택 UI를 추가한다.
오프라인 선택 시 기존 플레이어 수/이름 입력 화면으로 이동해 기존 startGame 흐름을 유지한다.
온라인 방 만들기와 참가 화면에 닉네임 입력 UI를 추가한다.
URL의 ?room= 값을 읽어 온라인 참가 화면으로 자동 진입한다.
WebSocket으로 서버의 command/createRoom, command/joinRoom을 호출한다.
대기실에서 방 코드, 공유 URL 후보, 복사 버튼, 참가자 목록을 표시한다.
참가자 목록에 방장, 나, 연결 상태를 표시한다.
서버 연결 실패와 참가 실패 메시지를 화면에 표시한다.
```

구현하지 않을 범위:

```text
게임 시작 서버 명령
초기 배치
주사위
게임 엔진 서버 이전
재접속 토큰 저장
방장 이전
```

1단계 피드백 반영 기준:

```text
클라이언트 요청은 type: "command" + payload.name 형식을 사용한다.
state 메시지의 top-level revision을 우선 기준으로 저장한다.
roomCreated 응답의 state와 이후 state broadcast를 같은 렌더 함수로 처리한다.
```

검증 방법:

```text
node --check server.js
node --check script.js
테스트 서버 실행 후 브라우저에서 첫 화면 모드 선택 확인
오프라인 게임 선택 후 기존 시작 흐름 확인
방 만들기 후 대기실 방 코드/공유 URL/참가자 목록 확인
?room= URL 접속 후 참가 화면 자동 진입 확인
두 브라우저 컨텍스트에서 참가자 목록 동기화 확인
서버 미연결 포트에서 연결 실패 안내 확인
```

## 2026-05-26 리뷰 피드백 반영 계획

최종 보고서 하단 리뷰 피드백에 따라 2단계 대기실 동작을 다음처럼 보완한다.

변경 대상:

```text
server.js
script.js
styles.css
docs/tests/2026-05-26_online-02-ui-lobby-test-plan.md
docs/reports/2026-05-26_online-02-ui-lobby-final-report.md
```

보완 범위:

```text
나가기 정책은 "방에서 제거"로 결정한다.
클라이언트가 나가기 버튼을 누르면 leaveRoom command를 서버에 보낸 뒤 소켓을 닫는다.
서버는 leaveRoom을 인증된 playerId/playerToken 기준으로 처리한다.
참가자가 나가면 players 배열에서 제거하고 남은 참가자에게 state를 broadcast한다.
방장이 나가고 남은 참가자가 있으면 첫 참가자에게 방장을 넘긴다.
빈 방은 메모리 rooms에서 제거한다.
게임 시작 버튼은 이번 단계 미구현 상태가 시각적으로 더 분명하도록 muted 처리한다.
```

검증 방법:

```text
node --check server.js
node --check script.js
WebSocket createRoom/joinRoom/leaveRoom 후 남은 참가자 목록 확인
방장 leaveRoom 후 방장 이전 확인
대기실 게임 시작 버튼 disabled 및 muted class 확인
```
