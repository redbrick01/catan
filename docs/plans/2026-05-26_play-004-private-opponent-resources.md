# 수정 계획서: PLAY-004 상대 자원 구성 비공개 처리

작성일: 2026-05-26  
관련 문제 문서: `docs/issues/2026-05-26_playability-issues.md`  
대상 파일: `script.js`, `styles.css`

## 1. 목적

상대 플레이어의 자원 종류별 보유량을 숨기고, 실제 Catan처럼 총 자원 카드 수만 공개한다.

## 2. 현재 문제

`renderSeats()`는 모든 플레이어에 대해 자원별 수량을 표시한다.

문제:

- 상대가 목재, 벽돌, 밀 등을 몇 장 가지고 있는지 모두 보인다.
- 독점 카드와 도둑 대상 선택이 지나치게 쉬워진다.
- 교환 협상의 정보 비대칭이 사라진다.

## 3. 수정 방향

현재 플레이어와 상대 플레이어 UI를 분리한다.

- 현재 플레이어: 자원 종류별 수량 표시
- 상대 플레이어: 총 자원 카드 수만 표시

추가로 개발 카드도 다음 정책을 유지한다.

- 현재 플레이어: 개발 카드 종류 요약 표시 가능
- 상대 플레이어: 개발 카드 총 장수만 표시

## 4. 구조 변경 여부

이 계획의 1차 수정은 전체 구조 변경 없이 진행한다.

1차 범위:

- 좌석 UI와 플레이어 목록에서 상대 자원 종류별 수량을 숨긴다.
- 현재 플레이어는 자신의 자원 종류별 수량을 계속 볼 수 있다.
- 상대는 총 자원 카드 수와 개발 카드 총 장수만 볼 수 있다.

전체 구조 변경이 필요한 범위:

- 한 화면을 여러 사람이 같이 보는 핫시트 환경에서 실제 비밀을 보장한다.
- 턴 전환 시 이전 플레이어 정보가 남지 않도록 가림 화면을 추가한다.
- 플레이어별 별도 디바이스/브라우저 화면을 제공한다.
- 서버가 각 플레이어별 공개 가능 정보만 내려주는 구조로 바꾼다.

따라서 이번 계획은 "공용 화면에서 불필요한 공개를 줄이는 UI 수정"이며, 완전한 비밀 정보 보호는 별도 작업이다.

## 5. 구현 계획

1. `renderSeats()`에서 `index === game.active` 여부를 기준으로 현재 플레이어를 판정한다.
2. 현재 플레이어는 기존 자원별 `mini-card` 표시를 유지한다.
3. 상대 플레이어는 `자원 총 N장`, `개발 N장` 형태로 표시한다.
4. `renderPlayers()` 목록도 같은 공개 정보 원칙으로 정리한다.
5. CSS에서 총량 표시용 `mini-card wide` 또는 별도 클래스를 추가한다.
6. `renderCurrentPlayerDevCards()`와 `harborPanel`은 현재 플레이어 전용 정보로 유지한다.

## 6. 세부 구현 체크리스트

대상 함수:

- `renderSeats()`
- `renderPlayers()`
- `resourceCount(player)`
- `renderCurrentPlayerDevCards()`
- `showRobberVictimModal()`
- `showPlayerTradeModal()`

정보 공개 정책:

| 정보 | 현재 플레이어 | 상대 플레이어 | 비고 |
| --- | --- | --- | --- |
| 자원 총 장수 | 공개 | 공개 | 실제 규칙상 공개 가능한 정보 |
| 자원 종류별 수량 | 공개 | 비공개 | 핵심 수정 대상 |
| 개발 카드 총 장수 | 공개 | 공개 | 이미 카드 뒷면 수량은 알 수 있음 |
| 개발 카드 종류 | 공개 | 비공개 | PLAY-003과 정책 일치 |
| 기사 사용 수 | 공개 | 공개 | 최대 기사력 판단에 필요 |
| 보너스 보유 | 공개 | 공개 | 최장 교역로/최대 기사력 |

권장 렌더링 구조:

```js
const isCurrent = index === game.active;
const resourceHtml = isCurrent
  ? renderResourceBreakdown(player)
  : renderResourceSummary(player);
```

추가하면 좋은 작은 헬퍼:

- `renderResourceBreakdown(player)`
- `renderResourceSummary(player)`
- `renderDevSummary(player, isCurrent)`

도둑 대상 모달 정책:

- 도둑으로 훔칠 때도 상대의 총 자원 수만 표시한다.
- 현재 코드의 `자원 N장` 표시는 유지 가능하다.
- 훔친 자원 종류는 도둑 사용자에게만 로그로 보여줄지 여부를 결정한다.

교환 모달 정책:

- 교환 제안 작성 화면에서 상대에게 요청할 자원을 선택하려면 상대 자원 종류를 어느 정도 알아야 하는 UI가 된다.
- 실제 보드게임에서도 상대가 협상 중 자기 보유 여부를 말할 수 있으므로, 1차 수정에서는 교환 모달 안에서만 상대 보유량을 표시할지 결정해야 한다.
- 권장 1차 정책: 좌석과 목록에서는 숨기고, 교환 모달의 요청 편집기는 현재 구현을 유지한다.
- 권장 2차 정책: 교환 모달도 상대 보유량 숫자는 숨기고 요청 수량만 구성하게 한다.

이번 작업의 권장 범위:

- 좌석과 플레이어 목록의 공개 정보부터 수정한다.
- 교환 모달은 PLAY-007에서 별도로 다룬다.

## 7. 테스트 시나리오

### TC-001: 현재 플레이어만 자원 종류별 수량 표시

사전 조건:

- 4인 게임
- 각 플레이어에게 서로 다른 자원 구성 지급
- 플레이어 1 차례

기대 결과:

- 플레이어 1 좌석에는 목재/벽돌/양/밀/광석 각각의 수량이 보인다.
- 플레이어 2~4 좌석에는 자원 총 장수만 보인다.

### TC-002: 턴 전환 시 공개 대상 변경

절차:

1. 플레이어 1 차례 UI를 확인한다.
2. 턴 종료로 플레이어 2 차례로 넘긴다.
3. 좌석 표시를 다시 확인한다.

기대 결과:

- 플레이어 1의 자원 종류별 수량은 숨겨진다.
- 플레이어 2의 자원 종류별 수량이 보인다.

### TC-003: 상대 총 자원 수는 유지

사전 조건:

- 상대 플레이어가 자원 7장 보유

기대 결과:

- 상대 좌석 또는 목록에 `자원 7장` 수준의 총량은 표시된다.
- 어떤 자원이 몇 장인지는 표시되지 않는다.

### TC-004: 개발 카드 종류 비공개와 충돌 없음

사전 조건:

- 상대가 개발 카드 3장 보유

기대 결과:

- 상대에게는 `개발 3장`만 표시된다.
- 종류별 개발 카드 정보는 현재 플레이어 패널에만 나온다.

## 8. 완료 기준

- 현재 차례 플레이어는 자신의 자원 종류별 수량을 볼 수 있다.
- 상대 플레이어의 자원 종류별 수량은 보이지 않는다.
- 상대 플레이어의 총 자원 카드 수는 계속 보인다.
- 턴이 넘어가면 새 현재 플레이어 기준으로 표시 권한이 바뀐다.

## 9. 검증 방법

- `node --check script.js`
- 3인 또는 4인 게임을 시작한다.
- 각 플레이어에게 서로 다른 자원을 부여한다.
- 현재 플레이어 좌석만 자원별 수량을 표시하는지 확인한다.
- 턴 종료 후 표시 대상이 다음 플레이어로 바뀌는지 확인한다.

## 10. UI 세부 기준

- 총량 표시 카드는 기존 `mini-card`와 높이를 맞춘다.
- 텍스트는 `자원 7` 또는 `자원 7장`처럼 짧게 유지한다.
- 좌석 카드 높이가 턴 전환마다 크게 흔들리지 않게 한다.
- 모바일에서 `자원 12장` 같은 두 자리 숫자가 넘치지 않게 한다.

## 11. 위험 요소

- 핫시트 게임에서는 화면을 함께 보면 현재 플레이어의 손패가 다른 사람에게 보일 수 있다.
- 완전한 비공개를 원하면 턴 전환 시 가림 화면 또는 패스 화면이 추가로 필요하다.
- 기존 UI 테스트가 자원별 카드 개수를 모든 좌석에서 찾고 있다면 갱신이 필요하다.

## 12. 롤백 방법

`renderSeats()`와 `renderPlayers()`의 현재/상대 분기를 제거하고 기존 자원별 표시로 되돌린다.
