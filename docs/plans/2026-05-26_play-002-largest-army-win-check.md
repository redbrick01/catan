# 수정 계획서: PLAY-002 최대 기사력 승리 체크 누락

작성일: 2026-05-26  
관련 문제 문서: `docs/issues/2026-05-26_playability-issues.md`  
대상 파일: `script.js`

## 1. 목적

기사 카드 사용으로 최대 기사력 보너스를 획득하고 10점에 도달한 경우 즉시 승리 처리되도록 한다.

## 2. 현재 문제

`playKnight()`는 기사 카드 사용 후 다음 처리를 수행한다.

- 개발 카드 제거
- 기사 수 증가
- `selectedAction = "robber"` 설정
- `updateLargestArmy()` 호출
- 도둑 이동 안내 로그 기록
- 렌더링

하지만 `updateLargestArmy()`로 2점 보너스가 새로 생긴 뒤 `checkWin()`을 호출하지 않는다.

## 3. 수정 범위

- `playKnight()`에서 `updateLargestArmy()` 이후 승리 체크를 수행한다.
- 승리하더라도 기사 카드의 도둑 이동 의무는 어떻게 처리할지 정책을 명확히 한다.

## 4. 정책 결정

권장 정책:

- 기사 카드 사용으로 10점에 도달하면 즉시 승리 처리한다.
- 승리 처리 후에는 추가 행동 버튼이 비활성화되므로 도둑 이동을 강제하지 않는다.

이유:

- Catan은 자기 턴에 10점 이상이 되면 승리한다.
- 게임 종료 후 도둑 이동을 완료하게 강제하는 것은 사용자에게 불필요한 후처리처럼 느껴진다.

## 5. 구현 계획

1. `playKnight(cardId)`에서 `updateLargestArmy()` 직후 `checkWin()`을 호출한다.
2. `checkWin()` 후 `game.winner !== null`이면 도둑 이동 상태를 해제하거나 렌더링 안내가 승리 상태를 우선 표시하는지 확인한다.
3. 현재 `guideFor()`가 게임 종료를 우선 표시하므로, 최소 수정은 `checkWin()` 호출 추가로 충분한지 검토한다.
4. 필요하면 승리 시 `selectedAction = "road"`로 정리해 강제 처리 상태가 남지 않게 한다.

## 6. 세부 구현 체크리스트

대상 함수:

- `playKnight(cardId)`
- `updateLargestArmy()`
- `checkWin()`
- `isResolvingForcedAction()`
- `renderControls()`
- `guideFor()`

변경 포인트:

- `player.knights += 1` 이후 최대 기사력 후보가 바뀐다.
- `updateLargestArmy()` 호출 뒤 실제 점수가 바뀔 수 있다.
- 승리하지 않은 경우에는 기존처럼 `selectedAction = "robber"` 상태가 유지되어야 한다.
- 승리한 경우에는 게임 종료 안내가 우선되어야 하고, 도둑 이동 강제 상태가 버튼 상태를 이상하게 만들면 안 된다.

권장 흐름:

```js
player.knights += 1;
selectedAction = "robber";
updateLargestArmy();
checkWin();
if (game.winner !== null) {
  selectedAction = "road";
  addLog(`${player.name}: 기사 사용.`);
} else {
  addLog(`${player.name}: 기사 사용. 도둑을 옮기세요.`);
}
render();
```

검토할 대안:

- 승리했더라도 도둑 이동을 완료하도록 유지한다.
- 이 대안은 규칙 후처리에는 엄격하지만, 이미 승리한 사용자에게 불필요한 행동을 요구하므로 권장하지 않는다.

수정하지 않을 것:

- 기사 카드 사용 가능 조건
- 이번 턴 구매 카드 사용 제한
- 한 턴 개발 카드 1장 제한
- 최대 기사력 동률 규칙

## 7. 테스트 시나리오

### TC-001: 8점 플레이어가 최대 기사력 획득으로 10점 승리

사전 조건:

- 현재 플레이어 공개 점수 8점
- 현재 플레이어 기사 사용 수 2
- 다른 플레이어의 기사 사용 수는 2 이하
- 현재 플레이어가 사용 가능한 기사 카드를 보유
- `game.usedDevThisTurn === false`

절차:

1. 개발 카드 사용 모달을 연다.
2. 기사 카드를 사용한다.
3. 최대 기사력과 승리 상태를 확인한다.

기대 결과:

- 현재 플레이어 기사 수가 3이 된다.
- `game.largestArmy === currentPlayer().id`
- `game.winner === currentPlayer().id`
- 게임 종료 안내가 표시된다.
- 도둑 이동을 추가로 요구하지 않는다.

### TC-002: 기사 사용으로 최대 기사력은 얻지만 10점 미만

사전 조건:

- 현재 플레이어 공개 점수 6점
- 기사 사용 수 2
- 사용 가능한 기사 카드 보유

기대 결과:

- 최대 기사력은 획득한다.
- `game.winner`는 `null`이다.
- `selectedAction === "robber"`로 도둑 이동을 요구한다.

### TC-003: 동률이면 최대 기사력 탈환 없음

사전 조건:

- 다른 플레이어가 최대 기사력 보유자이고 기사 수 3
- 현재 플레이어 기사 수 2
- 현재 플레이어가 기사 카드 사용 후 기사 수 3이 됨

기대 결과:

- `game.largestArmy`는 기존 보유자 그대로 유지된다.
- 현재 플레이어는 최대 기사력 2점을 얻지 않는다.
- 승리 체크가 잘못 통과하지 않는다.

## 8. 완료 기준

- 8점 또는 9점 플레이어가 기사 카드로 최대 기사력 2점을 얻어 10점 이상이 되면 즉시 승리한다.
- 승리 후 주사위, 턴 종료, 건설, 교환 버튼이 비활성화된다.
- 최대 기사력 보유자가 동률로 유지되는 경우에는 부당하게 승리 체크가 변하지 않는다.
- 승리하지 않는 기사 사용은 기존처럼 도둑 이동으로 이어진다.

## 9. 검증 방법

- `node --check script.js`
- 테스트 헬퍼로 기사 카드와 점수 상태를 구성한다.
- 기사 카드 사용 후 `game.largestArmy`, `game.winner`, 로그를 확인한다.
- 승리하지 않는 기사 카드 사용에서는 도둑 이동 안내가 유지되는지 확인한다.

## 10. 추가 확인 항목

- 승리 직후 `isResolvingForcedAction()`이 true로 남아도 `guideFor()`가 게임 종료를 우선 표시하는지 확인한다.
- 승리 직후 모달이 열려 있지 않은지 확인한다.
- 기사 카드가 실제로 손패에서 제거되는지 확인한다.
- `game.usedDevThisTurn`은 승리 여부와 관계없이 true가 되어야 한다.

## 11. 위험 요소

- 승리와 도둑 이동 강제 상태가 동시에 남으면 UI 안내와 버튼 차단이 어긋날 수 있다.
- `updateLargestArmy()`의 동률 유지 규칙을 건드리면 보너스 탈환 규칙이 깨질 수 있다.

## 12. 롤백 방법

`playKnight()`에 추가한 승리 체크와 승리 시 상태 정리 코드를 제거한다.
