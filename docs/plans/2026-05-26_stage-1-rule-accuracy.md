# 구현 계획서: 1단계 규칙 정확도 우선 수정

작성일: 2026-05-26

## 1. 작업 목적

`docs/reference/rule-gap-analysis.md`의 1단계 항목을 구현해 현재 Catan 프로젝트의 핵심 규칙 정확도를 높인다.

## 2. 관련 규칙

- `docs/reference/catan-detailed-rules.md`
- `docs/reference/rule-gap-analysis.md`
- `docs/guides/development-process-guideline.md`

## 3. 현재 구현 상태

현재 프로젝트는 보드 생성, 초기 배치, 주사위, 자원 생산, 건설, 도둑 이동, 기사 카드, 최장 교역로, 4:1 은행 교환, 승리 판정을 지원한다.

다만 다음 규칙이 간소화되어 있다.

- 상대 건물이 있는 교차점을 통해 내 도로가 계속 이어지는 것으로 처리될 수 있다.
- 최장 교역로 계산에서 상대 건물 차단 규칙이 반영되지 않는다.
- 7이 나왔을 때 버릴 자원을 자동 선택한다.
- 도둑 약탈 대상이 여러 명이어도 자동으로 첫 번째 대상을 선택한다.
- 표시 문구의 한글 인코딩 상태를 점검해야 한다.

## 4. 문제점

1단계 규칙들은 게임 결과에 직접 영향을 준다. 특히 도로 연결, 최장 교역로, 7 처리, 도둑 약탈은 실제 Catan 규칙과 다르면 승점과 자원 흐름이 달라진다.

## 5. 구현 범위

- 한글 표시 문구 점검 및 필요한 범위의 문구 정리
- 도로 건설 연결 규칙 수정
- 최장 교역로 계산에서 상대 건물 차단 반영
- 7 카드 버리기 선택 UI 추가
- 도둑 약탈 대상 선택 UI 추가
- 위 기능을 위한 최소한의 상태 값과 UI 추가

## 6. 구현하지 않을 범위

- 개발 카드 전체 구현
- 한 턴 개발 카드 1장 제한
- 플레이어 간 교역
- 항구 교역
- 은행 자원 재고 시스템
- 대규모 UI 리디자인

## 7. 수정 대상

- `index.html`
- `styles.css`
- `script.js`

## 8. 구현 순서

1. 모달 UI 컨테이너를 HTML에 추가한다.
2. 모달 스타일을 CSS에 추가한다.
3. 게임 상태에 7 처리와 도둑 약탈 선택용 상태를 추가한다.
4. 도로 연결 규칙에서 상대 건물 차단을 반영한다.
5. 최장 교역로 DFS에서 상대 건물 차단을 반영한다.
6. 정착지 건설 이후 최장 교역로를 재계산한다.
7. 7이 나왔을 때 자동 폐기 대신 플레이어별 버릴 자원 선택 UI를 표시한다.
8. 도둑 이동 후 약탈 대상이 여러 명이면 대상 선택 UI를 표시한다.
9. 렌더링 및 버튼 비활성화 조건을 보완한다.
10. 주요 한글 문구를 점검하고 깨진 문자열을 정리한다.

## 9. 검증 방법 초안

- 서버 실행 후 브라우저에서 메인 화면이 정상 표시되는지 확인한다.
- 초기 배치, 주사위, 건설, 턴 넘기기 기본 흐름을 확인한다.
- 8장 이상 보유 상태에서 7 처리 UI가 뜨는지 확인한다.
- 버릴 카드 수량이 정확히 맞아야 완료되는지 확인한다.
- 도둑 이동 후 약탈 대상 선택 UI가 뜨는지 확인한다.
- 상대 건물이 도로 연결과 최장 교역로를 차단하는지 코드 레벨 시나리오로 확인한다.

## 10. 위험 요소

- 기존 상태 흐름에 새 pending 상태가 추가되면서 턴 종료 버튼 조건이 꼬일 수 있다.
- 모달이 열려 있는 동안 다른 보드 클릭이 허용되면 상태가 어긋날 수 있다.
- 최장 교역로 DFS 변경으로 기존 길이 계산이 달라질 수 있다.

## 11. 롤백 방법

문제가 발생하면 이번 작업에서 수정한 `index.html`, `styles.css`, `script.js` 변경분과 새 문서 파일을 되돌린다. 기존 `docs/reference/catan-detailed-rules.md`, `docs/reference/rule-gap-analysis.md`, `docs/guides/development-process-guideline.md`는 유지한다.
