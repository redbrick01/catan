# 구현 계획서: 4단계 교역 시스템 확장

작성일: 2026-05-26

## 1. 작업 목적

기본 은행 4:1 교환만 지원하던 현재 교역 시스템을 확장해, Catan 기본 규칙의 플레이어 간 교역과 항구 교역을 구현한다.

## 2. 관련 규칙

- `docs/reference/catan-detailed-rules.md`
- `docs/reference/rule-gap-analysis.md`
- `docs/guides/development-process-guideline.md`
- `docs/reports/2026-05-26_stage-3-development-cards-final-report.md`

## 3. 현재 구현 상태

현재 프로젝트의 교역 기능은 `bankTrade()`의 은행 4:1 교환만 지원한다.

현재 한계:

- 플레이어 간 교역이 없다.
- 항구 데이터가 없다.
- 3:1 항구와 특정 자원 2:1 항구가 없다.
- 교역 UI가 항상 4:1 교환처럼 표시된다.

## 4. 구현 범위

- 항구 데이터 생성
- 항구를 보드에 표시
- 항구 소유 판정
- 은행 교환 비율을 4:1, 3:1, 특정 자원 2:1로 확장
- 플레이어 간 교역 모달 추가
- 현재 턴 플레이어가 상대, 줄 자원, 받을 자원을 선택해 교환
- 자기 턴이 아닌 플레이어끼리의 교역 금지
- 주사위 이후, 강제 처리 상태가 아닐 때만 교역 가능

## 5. 구현하지 않을 범위

- 복수 자원 묶음 교역
- 상대의 수락/거절 인터랙션
- 항구를 실제 바다 변 양끝 교차점에 정확히 배치하는 고급 렌더링
- 교역 협상 채팅
- 은행 자원 재고 반영

이번 단계에서는 플레이 가능성을 우선해 단일 자원 1:1 플레이어 교환과 교차점 기반 항구 소유 판정을 구현한다.

## 6. 수정 대상

- `index.html`
- `styles.css`
- `script.js`

## 7. 데이터 구조 변경

항구 데이터:

```js
harbors = [
  {
    id: 0,
    vertexId: 12,
    type: "generic"
  },
  {
    id: 1,
    vertexId: 18,
    type: "forest"
  }
]
```

항구 종류:

- `generic`: 3:1
- `forest`: 목재 2:1
- `field`: 밀 2:1
- `pasture`: 양 2:1
- `hill`: 벽돌 2:1
- `mountain`: 철 2:1

## 8. 구현 순서

1. `index.html`에 플레이어 교환 버튼과 은행 교환 비율 표시 영역을 추가한다.
2. 항구 상태 배열을 추가한다.
3. 보드 생성 후 외곽 교차점에 항구를 배정한다.
4. 항구 렌더링 함수를 추가한다.
5. 항구 소유 판정과 교환 비율 계산 함수를 추가한다.
6. `bankTrade()`에서 항구 비율을 사용한다.
7. 플레이어 간 교역 모달을 추가한다.
8. 버튼 비활성화와 안내 문구를 보완한다.
9. 테스트 계획서 작성 후 코드 레벨 테스트를 수행한다.

## 9. 검증 방법 초안

- `node --check script.js`
- 항구가 9개 생성되는지 확인
- 특정 자원 항구 소유 시 해당 자원 2:1 교환이 되는지 확인
- 일반 항구 소유 시 3:1 교환이 되는지 확인
- 항구가 없으면 4:1 교환이 유지되는지 확인
- 플레이어 간 교역으로 자원이 양방향 이동하는지 확인
- 현재 턴 플레이어가 아닌 상대끼리 교역이 발생하지 않는지 확인
- 주사위 전 교역이 차단되는지 확인

## 10. 위험 요소

- 항구를 단일 교차점에 붙이는 단순화는 실제 보드의 항구 배치와 완전히 같지 않다.
- 단일 자원 1:1 플레이어 교환은 실제 협상의 일부만 구현한 것이다.
- 은행 재고 시스템이 없으므로 항구 교역에서 은행 재고 부족은 고려하지 않는다.

## 11. 롤백 방법

문제가 발생하면 `index.html`의 교역 버튼/라벨 추가, `styles.css`의 항구 스타일, `script.js`의 항구 및 플레이어 교역 관련 변경을 되돌린다.
