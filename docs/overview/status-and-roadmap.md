# 프로젝트 진행 상황과 발전 로드맵

작성일: 2026-05-27

## 요약

Catan은 현재 기본 플레이가 가능한 상태까지 구현되었습니다. 오프라인 Catan 규칙 보강, 온라인 WebSocket 기반 방 플레이, 서버 권위 게임 상태, 비공개 정보 필터링, 봇 플레이어, 주요 회귀 테스트 문서화가 완료되어 있습니다.

자동 테스트, WebSocket 회귀, 로컬 브라우저 smoke, 코드 기반 규칙/개인정보 감사 기준으로 남은 P0/P1 이슈는 없습니다. 다만 실제 Chrome 3기기 LAN 전체 플레이, 모바일/좁은 viewport, 일부 모달 클릭 흐름, 장시간 봇 플레이는 아직 최종 실기기 검증이 필요합니다.

| 영역 | 상태 | 요약 |
| --- | --- | --- |

| 온라인 멀티플레이 | MVP~핵심 기능 구현 완료 | 방 생성/참가, 공유 URL, 로비, 서버 권위 상태, 재접속, 주요 게임 명령 동기화 |

| 테스트 문서화 | 완료 | 구현 계획, 테스트 계획, 최종 보고서, known issues, 기능별 문서 허브 정리 |

## 완료된 주요 기능

### 오프라인 게임

- 3~4인 게임 설정
- 랜덤 보드 생성
- 사막과 도둑 배치
- 초기 정착지/도로 배치
- 두 번째 초기 정착지 시작 자원 지급
- 주사위 굴림과 자원 생산
- 도둑이 있는 지형의 생산 차단
- 7 처리와 도둑 이동
- 도로, 정착지, 도시 건설
- 은행/항구 교환
- 플레이어 간 교환
- 개발 카드 구매와 사용
- 최대 기사력, 최장 교역로, 10점 승리 판정

### 온라인 게임

- `node server.js` 기반 로컬 서버
- LAN 접속용 URL 안내
- 온라인 방 만들기와 참가
- 공유 URL 복사
- WebSocket 기반 상태 동기화
- revision 기반 서버 상태 갱신
- 새로고침 후 같은 플레이어 재접속
- 서버 권위 명령 검증
- 초기 배치, 턴, 생산, 건설, 교역, 개발 카드, 도둑 처리 동기화
- 플레이어별 private state 생성

### 봇 게임

- 로비에서 봇 추가/제거
- 봇 포함 인원으로 게임 시작
- 봇 초기 정착지/도로 자동 배치
- 봇 턴 자동 진행
- 봇 건설/교환/개발 카드 기본 판단
- 봇 pending action 자동 처리
- 봇 명령이 사람 명령과 같은 서버 검증 경로 통과

### 테스트와 문서

- 기능별 구현 계획과 최종 보고서 작성
- 온라인 8~12단계 WebSocket 회귀 테스트
- 온라인 10-1 정적 UI 테스트
- 봇 8~9단계 회귀 테스트
- 온라인 13단계 전체 회귀/공식 규칙 감사/known issues 정리
- 기능별 문서 허브 추가

## 추후 발전 로드맵

### 1단계: 실사용 QA 안정화

목표는 현재 구현을 "실제로 친구들과 플레이해도 되는 상태"로 확정하는 것입니다.

- Chrome 3기기 LAN 전체 플레이 검증
- 사람 3명, 사람 2명 + 봇 1명, 사람 1명 + 봇 2명 조합 검증
- 초기 배치부터 최소 3라운드 진행
- 7/도둑, 플레이어 교환, 개발 카드, 항구 교환을 실제 클릭으로 확인
- 모바일/좁은 화면 overflow 확인
- known issues P2 항목 재판정

완료 기준:

```text
P0/P1 없음
핵심 P2 실기기 검증 완료
실제 Chrome 3기기 플레이 보고서 작성
```

### 2단계: 규칙 edge case 강화

목표는 공식 규칙과 더 가까운 안정성을 확보하는 것입니다.

- 최장 교역로 복잡 케이스 테스트
- 도둑 피해자 후보와 자원 0장 케이스 재검증
- 은행 재고 부족 생산 케이스 추가 fixture
- 개발 카드 사용 타이밍과 승리 판정 edge case 보강
- 보드 생성 seed 또는 재현 가능한 테스트 fixture 검토

완료 기준:

```text
복잡 규칙별 fixture 테스트 추가
공식 규칙 감사 문서 갱신
온라인/오프라인 규칙 차이 목록 0건 또는 문서화
```

### 3단계: UX 개선

목표는 게임을 "동작하는 수준"에서 "편하게 플레이하는 수준"으로 올리는 것입니다.

- 교환 제안 작성 UX 개선: 보유량 초과 즉시 차단, 제안 요약, 상대별 응답 상태, 요청자/응답자 관점 문구 분리
- pending action 안내 문구와 선택 흐름 개선: 상황, 해야 할 일, 선택 조건, 완료 후 다음 단계를 모달 안에서 명확히 표시
- 게임 로그 필터 또는 중요 이벤트 강조: 도둑, 교환, 개발 카드, 승점 변화, 봇 행동을 타입별로 구분
- 턴 진행 안내 강화: 현재 누가 진행 중인지, 내 차례가 왔는지, 내 턴/상대 턴/봇 턴/pending action 중 무엇인지 상단 상태, 가이드, 플레이어 카드에서 명확히 표시
- 모바일 레이아웃 재검토: 현재 턴, 보드, 액션 버튼, 내 자원, 상대 요약, 로그 순서로 정보 우선순위 재배치
- 방 참가 실패, 재접속 실패, 연결 끊김 안내 개선: 오류 원인별 메시지와 사용자가 취할 다음 행동을 함께 제공

상세 계획:

- [3단계 UX 개선 구체화 계획](../plans/2026-05-27_stage-3-ux-improvement-deepening-plan.md)

완료 기준:

```text
주요 행동을 설명 없이 수행 가능
모바일/데스크톱에서 겹침과 overflow 없음
수동 QA에서 UI 혼동 항목 감소
```

### 4단계: 봇 품질 향상

목표는 봇을 단순 진행용에서 기본 전략 상대 수준으로 발전시키는 것입니다.

- 초기 배치 평가 함수 개선
- 자원 부족 기반 건설 목표 선택
- 항구와 보유 자원 기반 교환 판단 개선
- 상대 승점과 위협도 기반 도둑 선택
- 플레이어 교환 수락/거절 판단 개선
- 난이도별 판단 파라미터 분리

완료 기준:

```text
봇이 게임을 멈추지 않을 뿐 아니라 기본적으로 납득 가능한 선택을 함
난이도별 행동 차이 문서화
장시간 봇 soak test 통과
```

### 5단계: 게임성 피드백 강화

목표는 시각적 애니메이션, 모션, 아이콘, 이미지, 사운드를 통해 행동 결과와 중요한 사건을 더 직관적으로 느끼게 만드는 것입니다.

- 내 차례와 현재 진행자 강조 모션
- 주사위 굴림과 자원 생산 피드백
- 건설, 개발 카드, 교환 성공 피드백
- 7/도둑/pending action 긴장감 피드백
- 자원/행동/상태 아이콘 언어 정리
- 선택적 효과음과 볼륨/mute 설정
- `prefers-reduced-motion` 기반 모션 감소 대응

상세 계획:

- [게임성 강화를 위한 시각/모션/이미지/아이콘/사운드 계획](../plans/2026-05-27_game-feel-visual-audio-motion-plan.md)

완료 기준:

```text
중요한 행동 결과를 로그 없이도 화면에서 이해 가능
사운드를 꺼도 정보 손실 없음
모션 감소 설정에서도 핵심 상태 인지 가능
모바일/데스크톱에서 효과가 레이아웃을 깨지 않음
```

### 6단계: 배포와 운영 편의

목표는 사용자가 더 쉽게 실행하고 공유할 수 있게 만드는 것입니다.

- 실행 스크립트와 오류 메시지 개선
- 포트 충돌 안내
- 방장 네트워크 주소 안내 개선
- favicon과 기본 메타데이터 추가
- 설정 가능한 포트/호스트 문서화
- 패키징 또는 간단한 배포 가이드 작성

완료 기준:

```text
비개발자도 npm install, npm start 후 같은 LAN에서 접속 가능
문제 발생 시 README만 보고 기본 대응 가능
```

### 7단계: 장기 확장 후보

이 단계는 현재 기본 구현을 넘는 별도 프로젝트급 확장입니다.

- 계정/로그인
- 공개 서버 배포
- HTTPS와 외부 접속
- 방 목록과 매치메이킹
- 게임 저장/불러오기
- 관전 모드
- 리플레이
- 통계와 전적
- AI 난이도 고도화 또는 MCTS/utility AI 도입
- 테스트 자동화에 Playwright 기반 멀티 브라우저 시나리오 추가
