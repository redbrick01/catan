# 전체 기능 테스트 및 검증 계획서

작성일: 2026-05-26  
대상 프로젝트: 브라우저 기반 Catan 오리지널 게임  
대상 파일: `index.html`, `styles.css`, `script.js`, `server.js`

## 1. 목적

본 문서는 현재 구현된 Catan 게임의 모든 주요 기능이 규칙, 화면, 상태 전이, 예외 처리 관점에서 정상 동작하는지 검증하기 위한 통합 테스트 계획서이다.

검증 목표:

- 게임 시작부터 승리까지 전체 플레이 흐름이 끊기지 않는다.
- Catan 기본 규칙이 현재 구현 범위 안에서 일관되게 적용된다.
- 개발 카드, 교역, 항구, 은행 재고, 도둑, 최장 교역로, 최대 기사력 등 점수와 자원에 영향을 주는 기능이 정확하다.
- UI 패널, 모달, 버튼 비활성화, 로그가 현재 게임 상태와 일치한다.
- 오류 상황에서도 게임 상태가 깨지지 않는다.

## 2. 테스트 범위

### 2.1 포함 범위

- 3~4인 플레이어 설정
- 보드 생성, 지형, 숫자 토큰, 사막, 도둑 초기 위치
- 항구 생성과 표시
- 초기 마을/도로 배치
- 두 번째 초기 마을의 시작 자원 지급
- 턴 진행, 주사위, 자원 생산
- 7 처리: 카드 버리기, 도둑 이동, 약탈 대상 선택
- 도로, 마을, 도시 건설
- 건설 비용 지불과 은행 재고 반환
- 개발 카드 구매와 사용
- 기사, 도로 건설, 풍년, 독점, 승점 카드
- 은행 4:1 교환, 항구 3:1 및 2:1 교환
- 플레이어 간 1:1 교환
- 은행 자원 재고 부족 처리
- 최장 교역로, 최대 기사력
- 승리 판정
- 상태 패널, 카드 패널, 은행 재고 패널, 비용표, 보유 항구 패널
- 새 게임 및 리셋
- 로컬 정적 서버 응답

### 2.2 제외 범위

- 온라인 멀티플레이
- 저장/불러오기
- AI 플레이어
- 확장판 규칙
- 반응형 UI의 모든 기기 조합에 대한 완전한 시각 QA
- 브라우저별 호환성 전체 매트릭스

- OS: Windows
- 실행 셸: PowerShell
- 런타임: Node.js
- 로컬 서버: `node server.js`
- 기본 URL: `http://127.0.0.1:4173/`
- 브라우저: Codex in-app browser 또는 Chromium 계열 브라우저

필수 사전 조건:

- `index.html`, `styles.css`, `script.js`, `server.js`가 프로젝트 루트에 존재한다.

## 5. 테스트 데이터

기본 데이터:

- 플레이어 수: 3명, 4명 각각 1회 이상
- 플레이어 이름: 기본값, 사용자 입력값, 10자 제한 근접값
- 자원: 목재, 벽돌, 양, 밀, 철
- 개발 카드: 기사, 도로 건설, 풍년, 독점, 승점
- 항구: 일반 3:1, 자원별 2:1

경계 데이터:

- 보유 자원 0장
- 보유 자원 7장
- 보유 자원 8장
- 은행 재고 0장
- 은행 재고 1장
- 도로 말 부족
- 개발 카드 더미 고갈
- 9점에서 승점 카드 또는 보너스로 10점 도달

## 6. 기능별 테스트 시나리오

### TC-001 초기 화면과 플레이어 설정

절차:

1. 앱을 연다.
2. 플레이어 수를 3명으로 변경한다.
3. 이름 입력 필드가 3개인지 확인한다.
4. 플레이어 수를 4명으로 변경한다.
5. 이름 입력 필드가 4개인지 확인한다.
6. 이름을 입력하고 게임 시작을 누른다.

기대 결과:

- 설정 화면이 닫히고 게임 보드가 표시된다.
- 현재 플레이어가 첫 번째 플레이어로 설정된다.
- 플레이어 목록과 좌석에 이름, 색상, 점수, 자원 수가 표시된다.

### TC-002 보드 생성

절차:

1. 새 게임을 시작한다.
2. 보드의 지형 타일, 숫자 토큰, 도둑 위치를 확인한다.
3. 항구 표시를 확인한다.

기대 결과:

- 기본 보드는 19개 타일로 구성된다.
- 사막에는 숫자 토큰이 없다.
- 도둑은 사막에 위치한다.
- 항구는 9개 생성되고 보드 외곽에 표시된다.
- 일반 항구와 자원별 항구가 포함된다.

### TC-003 초기 배치 순서

절차:

1. 첫 플레이어부터 순서대로 마을과 도로를 놓는다.
2. 마지막 플레이어 이후 역순 배치가 시작되는지 확인한다.
3. 두 번째 마을을 놓을 때 인접 타일 자원이 지급되는지 확인한다.

기대 결과:

- 1차 배치는 정순, 2차 배치는 역순으로 진행된다.
- 마을은 거리 규칙을 만족하는 교차점에만 놓을 수 있다.
- 초기 도로는 방금 놓은 마을과 연결된 간선에만 놓을 수 있다.
- 두 번째 마을 인접 자원이 플레이어에게 지급되고 은행 재고가 차감된다.

### TC-004 턴 진행과 주사위 제한

절차:

1. 일반 플레이 단계에 진입한다.
2. 주사위를 굴리기 전 도로, 마을, 도시, 개발 카드 구매, 은행 교환, 플레이어 교환을 시도한다.
3. 주사위를 굴린다.
4. 같은 행동을 다시 시도한다.
5. 턴 넘기기를 누른다.

기대 결과:

- 주사위 전 후속 행동은 차단된다.
- 주사위 후 조건을 만족하는 행동은 허용된다.
- 턴이 넘어가면 현재 플레이어와 주사위 상태가 갱신된다.
- 한 턴에 주사위는 한 번만 굴릴 수 있다.

### TC-005 자원 생산

절차:

1. 특정 숫자 주변에 마을과 도시를 배치한 상태를 만든다.
2. 해당 숫자가 나오도록 테스트한다.
3. 도둑이 있는 타일과 없는 타일의 생산 결과를 비교한다.

기대 결과:

- 마을은 자원 1장, 도시는 자원 2장을 받는다.
- 도둑이 있는 타일은 생산하지 않는다.
- 은행 재고가 지급량만큼 감소한다.
- 생산 로그가 기록된다.

### TC-006 7 카드 버리기

절차:

1. 한 명 이상의 플레이어가 자원을 8장 이상 보유하게 한다.
2. 주사위 결과가 7이 되게 한다.
3. 카드 버리기 모달에서 부족, 초과, 정확한 수량을 각각 선택한다.
4. 모든 대상자의 버리기를 완료한다.

기대 결과:

- 8장 이상 보유자만 버리기 대상이 된다.
- 버릴 수량은 `Math.floor(보유 카드 / 2)`이다.
- 정확한 수량을 선택하기 전에는 완료할 수 없다.
- 버린 자원은 플레이어에게서 차감되고 은행에 반환된다.
- 모든 버리기 완료 후 도둑 이동 단계로 진행된다.

### TC-007 도둑 이동과 약탈

절차:

1. 7 처리 또는 기사 카드로 도둑 이동 상태를 만든다.
2. 현재 도둑이 있는 타일을 클릭한다.
3. 다른 타일을 클릭한다.
4. 인접 상대가 0명, 1명, 여러 명인 경우를 각각 확인한다.

기대 결과:

- 도둑은 현재 위치가 아닌 타일로만 이동할 수 있다.
- 약탈 가능한 상대가 없으면 즉시 일반 행동 단계로 돌아간다.
- 약탈 가능한 상대가 1명이면 해당 상대에게서 무작위 자원 1장을 가져온다.
- 약탈 가능한 상대가 여러 명이면 선택 모달이 표시된다.
- 선택한 상대에게서만 자원을 가져온다.

### TC-008 도로 건설

절차:

1. 도로 버튼을 선택한다.
2. 연결되지 않은 간선을 클릭한다.
3. 내 도로 또는 내 건물과 연결된 빈 간선을 클릭한다.
4. 상대 건물이 중간에 있는 연결 경로를 시도한다.

기대 결과:

- 비용은 목재 1장, 벽돌 1장이다.
- 연결 규칙을 만족하는 간선에만 도로를 놓을 수 있다.
- 상대 건물이 있는 교차점은 내 도로 연결점으로 인정되지 않는다.
- 도로 말 수가 차감된다.
- 비용은 은행에 반환된다.

### TC-009 마을 건설

절차:

1. 마을 버튼을 선택한다.
2. 인접 교차점에 다른 건물이 있는 위치를 클릭한다.
3. 내 도로와 연결되지 않은 위치를 클릭한다.
4. 거리 규칙과 연결 규칙을 모두 만족하는 위치를 클릭한다.

기대 결과:

- 비용은 목재 1장, 벽돌 1장, 양 1장, 밀 1장이다.
- 인접 건물이 있으면 건설할 수 없다.
- 일반 플레이 중에는 내 도로와 연결되어야 한다.
- 마을 말 수가 차감되고 점수가 증가한다.

### TC-010 도시 업그레이드

절차:

1. 도시 버튼을 선택한다.
2. 상대 마을 또는 빈 교차점을 클릭한다.
3. 내 마을을 클릭한다.

기대 결과:

- 비용은 밀 2장, 철 3장이다.
- 내 마을만 도시로 업그레이드할 수 있다.
- 마을 말은 반환되고 도시 말은 차감된다.
- 공개 점수가 1점 추가된다.

### TC-011 개발 카드 구매

절차:

1. 주사위 후 개발 카드 구매 버튼을 누른다.
2. 자원이 부족한 상태와 충분한 상태를 각각 확인한다.
3. 개발 카드 더미가 비어 있는 상태를 확인한다.

기대 결과:

- 비용은 양 1장, 밀 1장, 철 1장이다.
- 자원이 부족하면 구매되지 않는다.
- 구매한 카드는 `id`, `type`, `boughtTurn`을 가진 객체로 저장된다.
- 이번 턴에 구매한 카드는 같은 턴에 사용할 수 없다.
- 개발 카드 더미가 비면 구매할 수 없다.

### TC-012 개발 카드 사용 목록

절차:

1. 현재 플레이어에게 이전 턴에 구매한 개발 카드를 준비한다.
2. 카드 사용 버튼을 누른다.
3. 이번 턴 구매 카드와 승점 카드가 목록에 표시되는지 확인한다.

기대 결과:

- 사용 가능한 기사, 도로 건설, 풍년, 독점 카드만 표시된다.
- 승점 카드는 사용 목록에서 제외된다.
- 이번 턴에 구매한 카드는 사용 목록에서 제외된다.
- 한 턴에 이미 개발 카드를 사용했다면 카드 사용이 차단된다.

### TC-013 기사 카드

절차:

1. 기사 카드를 사용한다.
2. 도둑을 이동한다.
3. 약탈 대상이 있으면 약탈한다.

기대 결과:

- 기사 카드가 손패에서 제거된다.
- 사용한 기사 수가 1 증가한다.
- 도둑 이동 단계로 전환된다.
- 최대 기사력 조건을 만족하면 보너스가 갱신된다.
- 같은 턴에 다른 개발 카드를 추가로 사용할 수 없다.

### TC-014 도로 건설 카드

절차:

1. 도로 건설 카드를 사용한다.
2. 합법적인 도로 위치를 두 번 선택한다.
3. 도로 말이 부족하거나 합법 위치가 없는 경우를 확인한다.

기대 결과:

- 카드가 손패에서 제거된다.
- 도로 비용은 차감되지 않는다.
- 도로 말은 배치 수만큼 차감된다.
- 최대 2개의 무료 도로를 놓은 뒤 일반 상태로 돌아간다.
- 도로 건설 카드 진행 중 턴 종료는 차단된다.

### TC-015 풍년 카드

절차:

1. 풍년 카드를 사용한다.
2. 서로 다른 자원 2장을 선택한다.
3. 같은 자원 2장을 선택한다.
4. 은행 재고가 0장 또는 1장인 자원을 선택해 본다.

기대 결과:

- 선택한 자원 2장이 현재 플레이어에게 지급된다.
- 은행 재고가 선택 수량만큼 감소한다.
- 은행에 없는 자원은 선택할 수 없다.
- 은행에 1장뿐인 자원은 두 번 선택할 수 없다.

### TC-016 독점 카드

절차:

1. 독점 카드를 사용한다.
2. 자원 종류 하나를 선택한다.
3. 모든 상대의 해당 자원 수량을 확인한다.

기대 결과:

- 선택한 자원은 모든 상대에게서 현재 플레이어에게 이동한다.
- 상대의 해당 자원은 0장이 된다.
- 은행 재고는 변하지 않는다.
- 획득 총량이 로그에 기록된다.

### TC-017 승점 카드

절차:

1. 승점 카드를 보유한 플레이어를 만든다.
2. 플레이어 목록과 현재 카드 패널을 확인한다.
3. 10점 도달 조건을 확인한다.

기대 결과:

- 승점 카드는 별도 사용 없이 점수 계산에 포함된다.
- 다른 플레이어에게 과도하게 비공개 정보가 노출되지 않는지 확인한다.
- 승리 판정에는 승점 카드 점수가 포함된다.

### TC-018 은행/항구 교환

절차:

1. 항구가 없는 플레이어로 은행 교환을 수행한다.
2. 일반 3:1 항구 보유 플레이어로 교환한다.
3. 특정 자원 2:1 항구 보유 플레이어로 해당 자원과 다른 자원을 각각 교환한다.
4. 은행에 받을 자원이 없는 상태를 만든다.

기대 결과:

- 항구가 없으면 4:1 비율이 적용된다.
- 일반 항구가 있으면 3:1 비율이 적용된다.
- 특정 자원 항구는 해당 자원에만 2:1 비율이 적용된다.
- 플레이어가 낸 자원은 은행으로 돌아가고 받은 자원은 은행에서 차감된다.
- 은행에 받을 자원이 없으면 교환되지 않는다.

### TC-019 플레이어 간 교환

절차:

1. 주사위 후 플레이어 교환을 선택한다.
2. 교환 상대, 줄 자원, 받을 자원을 선택한다.
3. 한쪽 자원이 부족한 경우를 확인한다.

기대 결과:

- 현재 턴 플레이어와 선택한 상대 사이에서만 교환된다.
- 양쪽 모두 선택 자원을 1장 이상 보유해야 한다.
- 교환 성공 시 양쪽 자원이 정확히 1장씩 이동한다.
- 은행 재고는 변하지 않는다.

### TC-020 은행 재고 부족

절차:

1. 특정 자원의 은행 재고를 필요한 지급량보다 적게 만든다.
2. 주사위 생산, 풍년 카드, 은행 교환을 각각 시도한다.

기대 결과:

- 생산 시 특정 자원 지급 총량이 은행 재고보다 많으면 그 자원은 아무도 받지 못한다.
- 풍년 카드는 은행 재고 안에서만 선택 가능하다.
- 은행 교환은 받을 자원의 은행 재고가 1장 이상이어야 성공한다.

### TC-021 최장 교역로

절차:

1. 한 플레이어가 도로 5개 이상을 연결한다.
2. 다른 플레이어가 같은 길이의 도로를 만든다.
3. 상대 건물이 내 도로 중간에 끼는 상황을 만든다.
4. 기존 보유자를 앞지르는 길이를 만든다.

기대 결과:

- 길이 5 이상 단독 최장 도로 보유자에게 2점 보너스가 부여된다.
- 동률이면 기존 보유자가 유지된다.
- 기존 보유자가 없고 동률이면 보너스가 부여되지 않는다.
- 상대 건물은 내 도로 연속성을 끊는다.

### TC-022 최대 기사력

절차:

1. 한 플레이어가 기사 카드를 3장 사용한다.
2. 다른 플레이어가 같은 수의 기사를 사용한다.
3. 다른 플레이어가 더 많은 기사를 사용한다.

기대 결과:

- 기사 3장 이상 단독 최다 사용자에게 2점 보너스가 부여된다.
- 동률이면 기존 보유자가 유지된다.
- 더 많은 기사를 사용한 플레이어가 보너스를 가져간다.

### TC-023 승리 판정

절차:

1. 현재 턴 플레이어를 9점으로 만든다.
2. 건설, 개발 카드 점수, 최장 교역로, 최대 기사력 중 하나로 10점에 도달하게 한다.
3. 현재 턴이 아닌 플레이어가 10점 이상인 상태를 만든다.

기대 결과:

- 현재 턴 플레이어가 10점 이상이면 게임 종료 상태가 된다.
- 승리 메시지가 표시된다.
- 게임 종료 후 추가 행동이 차단된다.
- 현재 턴이 아닌 플레이어의 점수는 자신의 턴 승리 판정 시점에 처리되는지 확인한다.

### TC-024 UI 패널

절차:

1. 게임 시작 전과 게임 시작 후 각각 우측 패널을 확인한다.
2. 주사위 전, 주사위 후, 강제 처리 상태에서 턴 상태 패널을 확인한다.
3. 개발 카드, 은행 재고, 비용표, 보유 항구 패널을 확인한다.

기대 결과:

- 게임 상태가 없어도 패널 렌더링 오류가 없다.
- 턴 상태는 현재 단계, 라운드, 현재 플레이어, 주사위 상태를 반영한다.
- 개발 카드 패널은 현재 플레이어의 카드 종류와 수량을 표시한다.
- 은행 재고 패널은 자원별 남은 수량을 표시한다.
- 비용표는 도로, 마을, 도시, 개발 카드 비용을 표시한다.
- 보유 항구가 없으면 없음으로 표시되고, 있으면 항구 이름이 표시된다.

### TC-025 모달과 강제 처리 상태

절차:

1. 카드 버리기 모달, 약탈 대상 선택 모달, 개발 카드 선택 모달, 풍년/독점 모달, 플레이어 교환 모달을 각각 연다.
2. 모달 표시 중 다른 행동 버튼을 눌러 본다.
3. 모달 완료 후 정상 단계로 복귀하는지 확인한다.

기대 결과:

- 모달은 제목, 설명, 선택지, 완료 버튼을 명확하게 표시한다.
- 강제 처리 상태에서는 다른 행동이 차단된다.
- 완료 후 모달이 닫히고 다음 상태가 정확히 설정된다.

### TC-026 로그

절차:

1. 게임 시작, 초기 배치, 주사위, 생산, 건설, 교환, 개발 카드 사용, 도둑 이동, 승리 이벤트를 발생시킨다.
2. 로그 목록을 확인한다.

기대 결과:

- 주요 이벤트가 최신순 또는 의도한 순서로 기록된다.
- 로그 문구가 깨지지 않는다.
- 자원명, 플레이어명, 카드명, 수량이 실제 결과와 일치한다.

### TC-027 새 게임과 리셋

절차:

1. 진행 중인 게임에서 새 게임 버튼을 누른다.
2. 다시 게임을 시작한다.

기대 결과:

- 설정 화면으로 돌아간다.
- 이전 플레이어, 보드, 자원, 카드, 로그, 도둑, 보너스 상태가 새 게임에 영향을 주지 않는다.
- 은행 재고는 자원별 19장으로 초기화된다.

### TC-028 서버 응답

절차:

1. `node server.js`를 실행한다.
2. `http://127.0.0.1:4173/`에 접속한다.
3. `index.html`, `styles.css`, `script.js` 요청이 정상 응답하는지 확인한다.
4. 존재하지 않는 경로를 요청한다.

기대 결과:

- 루트 경로는 `index.html`을 반환한다.
- 정적 파일은 올바른 content-type과 함께 200으로 응답한다.
- 없는 파일은 404를 반환한다.
- 상위 경로 접근 시도가 허용되지 않는다.

## 8. 비기능 검증

### 8.1 사용성

- 버튼 이름이 현재 행동을 이해하기 쉽다.
- 비활성화된 버튼은 클릭해도 상태가 변하지 않는다.
- 모달에서 필요한 선택 수량과 현재 선택 수량을 알 수 있다.
- 비용표와 은행 재고가 플레이 의사결정에 충분한 정보를 제공한다.

### 8.2 안정성

- 빠른 연속 클릭으로 중복 건설 또는 중복 주사위가 발생하지 않는다.
- 모달이 열린 상태에서 상태가 꼬이지 않는다.
- 자원 수량이 음수가 되지 않는다.
- 말 수가 음수가 되지 않는다.
- 은행 재고가 음수가 되지 않는다.

### 8.3 접근성과 표시

- 주요 UI 텍스트가 한국어로 정상 표시된다.
- 보드 SVG가 화면에서 잘리지 않는다.
- 우측 패널이 긴 내용에서도 스크롤 가능하다.
- 모달 내용이 작은 화면에서 화면 밖으로 과도하게 벗어나지 않는다.

## 9. 결함 기록 기준

결함은 아래 형식으로 기록한다.

- ID
- 발견일
- 테스트 케이스 ID
- 심각도: Critical, Major, Minor, Trivial
- 재현 절차
- 실제 결과
- 기대 결과
- 관련 파일 또는 함수
- 스크린샷 또는 로그
- 상태: Open, In Progress, Fixed, Verified, Won't Fix

심각도 기준:

- Critical: 게임 진행 불가, 데이터 심각 손상, 승리/점수 치명 오류
- Major: 주요 규칙 오류, 자원/카드/교역 결과 불일치
- Minor: 특정 조건의 UI 오류, 로그 누락, 보조 정보 불일치
- Trivial: 문구, 정렬, 사소한 표시 문제

## 10. 완료 기준

전체 테스트는 아래 조건을 만족하면 완료로 본다.

- `node --check script.js`와 `node --check server.js`가 통과한다.
- TC-001부터 TC-028까지 Critical 또는 Major 결함 없이 통과한다.
- 남은 Minor 또는 Trivial 결함은 재현 절차와 영향 범위가 문서화되어 있다.
- 최소 1회 이상 3인 게임과 4인 게임 시작 흐름이 검증되었다.
- 최소 1회 이상 10점 승리 흐름이 검증되었다.
- 은행 재고, 개발 카드, 교역, 도둑, 보너스 점수 기능이 각각 독립적으로 검증되었다.
