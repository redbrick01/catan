## 4. 발견 결함

### BUG-001: 기사 카드로 도둑 이동 시작 시 안내 문구가 도둑 이동을 표시하지 않음

- 심각도: Major
- 상태: Fixed, Verified
- 관련 테스트: TC-004, TC-007, TC-013, TC-025
- 관련 파일: `script.js`
- 관찰 결과:
  - 이전 턴에 구매한 기사 카드를 주사위 전 사용하면 로그에는 `기사 사용. 도둑을 옮기세요.`가 기록된다.
  - 하지만 턴 상태 패널은 `주사위 또는 개발 카드 / 주사위를 굴리세요...`를 계속 표시한다.
- 기대 결과:
  - 기사 카드 사용 직후에는 `도둑 이동 / 도둑을 다른 타일로 옮기세요...`가 표시되어야 한다.
- 원인 추정:
  - `guideFor()`에서 `!game.rolled` 조건이 `selectedAction === "robber"`보다 먼저 평가되어, 주사위 전 강제 도둑 이동 상태가 가려진다.
- 수정 내용:
  - `guideFor()`에서 카드 버리기, 도둑 이동, 약탈 대상 선택, 도로 건설 카드 같은 강제 처리 안내를 주사위 전 안내보다 먼저 평가하도록 순서를 변경했다.
- 재검증:
  - 도둑 이동 상태에서 안내 패널이 `도둑 이동`을 우선 표시하는 것을 확인했다.

### BUG-002: 기사 카드로 도둑 이동 중 주사위 버튼이 활성화됨

- 심각도: Major
- 상태: Fixed, Verified
- 관련 테스트: TC-004, TC-007, TC-013
- 관련 파일: `script.js`
- 관찰 결과:
  - 기사 카드 사용 후 도둑 이동이 끝나기 전 `rollButton`이 활성화되어 있었다.
  - 행동 버튼들은 비활성화되었지만 주사위 버튼만 활성화 상태였다.
- 기대 결과:
  - 도둑 이동 또는 약탈 대상 선택 같은 강제 처리 상태에서는 주사위 버튼도 비활성화되어야 한다.
- 원인 추정:
  - `renderControls()`의 `rollButton.disabled` 조건에 `isResolvingForcedAction()`이 포함되어 있지 않다.
- 수정 내용:
  - `rollButton.disabled`와 `endTurnButton.disabled` 조건에 강제 처리 상태 판정을 반영했다.
  - `roll()`과 `endTurn()` 함수 자체도 강제 처리 상태에서는 실행되지 않도록 방어 조건을 보강했다.
- 재검증:
  - 도둑 이동, 약탈 대상 선택, 카드 버리기 같은 강제 처리 상태에서 주사위와 턴 종료가 차단되도록 확인했다.

### BUG-003: 플레이어 간 교환에 상대 수락 절차가 없음

- 심각도: Major
- 상태: Fixed, Verified
- 관련 테스트: TC-019
- 관련 파일: `script.js`
- 관찰 결과:
  - `showPlayerTradeModal()`에서 현재 턴 플레이어가 상대, 줄 자원, 받을 자원을 선택한 뒤 `교환` 버튼을 누르면 즉시 자원이 이동한다.
  - 선택된 상대 플레이어가 제안을 확인하거나 수락/거절하는 절차가 없다.
- 기대 결과:
  - 현재 턴 플레이어는 교환 제안을 만들고, 상대 플레이어가 수락한 경우에만 자원이 이동해야 한다.
  - 상대가 거절하면 자원 상태가 변하지 않아야 한다.
  - 제안 수량과 자원 보유량은 수락 시점에도 다시 검증되어야 한다.
- 원인:
  - 현재 구현이 플레이어 간 교역을 "상대와 자원 1장씩 즉시 교환"하는 단일 확인 버튼으로 처리한다.
- 수정 내용:
  - 현재 턴 플레이어가 상대를 고른 뒤, 자원별 수량으로 제공 자원과 요청 자원을 구성하도록 변경했다.
  - 제안 버튼을 누르면 상대 플레이어에게 수락/거절 확인 모달이 표시된다.
  - 수락 시점에 양쪽 자원 보유량을 다시 검증하고, 조건을 만족할 때만 자원을 이동한다.
- 재검증:
  - 플레이어 1이 `목재 1, 곡물 1`을 제공하고 플레이어 2에게 `곡물 1`을 요청하는 제안을 생성했다.
  - 제안 확인 화면에서 수락 전까지 자원은 이동하지 않았다.
  - 수락 후 플레이어 1의 목재가 1장 감소하고, 플레이어 2의 목재가 1장 증가했다.
  - 브라우저 콘솔 오류는 없었다.
