# 수정 계획서: PLAY-006 보드 랜덤 배치 밸런스 제약 추가

작성일: 2026-05-26  
관련 문제 문서: `docs/known_issues/2026-05-26_playability-issues.md`  
대상 파일: `script.js`

## 1. 목적

보드 랜덤 생성 시 6과 8 숫자 토큰이 인접하지 않도록 해, 게임 시작 밸런스 편차를 줄인다.

## 2. 현재 문제

`setupBoard()`는 지형과 숫자 배열을 단순 셔플한다.

문제:

- 6과 8이 서로 인접할 수 있다.
- 높은 생산 숫자가 특정 지역에 몰릴 수 있다.
- 초반 정착지 선택의 유불리가 과도하게 커질 수 있다.

## 3. 수정 범위

첫 개선 범위는 다음으로 제한한다.

- 6과 8이 서로 인접하지 않도록 숫자 배치 재시도
- 사막에는 숫자를 배치하지 않는 기존 규칙 유지
- 지형 랜덤 배치는 기존 방식 유지

추가 밸런스 규칙은 후속 작업으로 둔다.

- 같은 자원 고확률 집중 방지
- 항구와 자원 생산 위치 조합 조정
- 공식 초보자 보드 프리셋 제공

## 4. 구현 계획

1. 타일 좌표 생성 후 인접 타일을 판정하는 헬퍼를 만든다.
2. 숫자 토큰 배열을 섞어 비사막 타일에 배치한다.
3. 배치 결과에서 6/8 인접 여부를 검사한다.
4. 실패하면 제한 횟수까지 다시 섞는다.
5. 제한 횟수 초과 시 기존 셔플 결과를 사용하되 로그 또는 주석으로 fallback을 명시한다.

## 5. 세부 구현 체크리스트

대상 함수:

- `setupBoard()`
- 새 함수 `areTilesAdjacent(tileA, tileB)`
- 새 함수 `hasAdjacentHotNumbers(candidateTiles)`
- 새 함수 `assignBalancedNumbers(nonDesertTiles)`

인접 판정:

- 두 타일이 edge를 공유하면 인접이다.
- 현재 데이터에서는 두 타일의 `vertexIds` 교집합 크기가 2 이상이면 edge를 공유한다고 볼 수 있다.
- 꼭짓점 하나만 공유하는 경우는 인접으로 보지 않는다.

권장 헬퍼:

```js
function areTilesAdjacent(a, b) {
  const shared = a.vertexIds.filter((id) => b.vertexIds.includes(id));
  return shared.length >= 2;
}
```

숫자 배치 절차:

1. 지형을 먼저 배치한다.
2. `type !== "desert"`인 타일 목록을 만든다.
3. 숫자 토큰 배열을 섞는다.
4. 비사막 타일 순서대로 숫자를 임시 배정한다.
5. 6/8 타일끼리 인접한 쌍이 있으면 실패로 본다.
6. 최대 300회 정도 재시도한다.
7. 성공하면 숫자를 확정한다.
8. 실패하면 마지막 후보 또는 단순 셔플 후보를 사용한다.

권장 상수:

```js
const MAX_NUMBER_ASSIGNMENT_ATTEMPTS = 300;
const HOT_NUMBERS = new Set([6, 8]);
```

fallback 정책:

- 무한 루프는 절대 허용하지 않는다.
- fallback이 발생해도 게임은 시작되어야 한다.
- fallback 발생 시 개발용 로그를 남길 수 있지만, 사용자 로그에는 노출하지 않는 편이 좋다.

수정하지 않을 것:

- 지형 타일 개수
- 숫자 토큰 구성
- 사막에 숫자를 두지 않는 규칙
- 주사위 생산 로직

## 6. 테스트 시나리오

### TC-001: 단일 보드 생성에서 6/8 인접 없음

절차:

1. 새 게임을 시작한다.
2. 숫자 6 또는 8이 놓인 타일 목록을 수집한다.
3. 모든 6/8 타일 쌍의 인접 여부를 검사한다.

기대 결과:

- 6과 8을 가진 타일끼리 edge를 공유하지 않는다.

### TC-002: 반복 생성 안정성

절차:

1. 보드를 100회 이상 생성한다.
2. 각 보드에서 6/8 인접 여부를 검사한다.
3. 생성 시간이 눈에 띄게 느려지지 않는지 확인한다.

기대 결과:

- 모든 성공 케이스에서 6/8 인접이 없다.
- fallback 발생이 없거나 매우 드물다.
- 브라우저가 멈추지 않는다.

### TC-003: 숫자 토큰 구성 유지

기대 결과:

- 숫자 2와 12는 각각 1개다.
- 숫자 3, 4, 5, 6, 8, 9, 10, 11은 각각 2개다.
- 사막 타일의 `number`는 `null`이다.
- 비사막 타일 18개에는 숫자가 모두 있다.

### TC-004: 생산 로직 영향 없음

절차:

1. 특정 숫자를 강제로 굴리거나 테스트 헬퍼로 설정한다.
2. 해당 숫자 타일 주변 건물에 자원이 생산되는지 확인한다.

기대 결과:

- 숫자 배치 개선 후에도 `produce(total)`는 기존처럼 동작한다.

## 7. 완료 기준

- 정상 생성된 보드에서 6과 8 타일이 서로 인접하지 않는다.
- 사막은 숫자 토큰이 없다.
- 숫자 토큰 개수와 분포는 기존 기본판 구성과 같다.
- 보드 생성이 무한 루프에 빠지지 않는다.

## 8. 검증 방법

- `node --check script.js`
- 보드를 여러 번 생성해 6/8 인접이 없는지 검사한다.
- 100회 이상 반복 생성 테스트에서 실패율과 fallback 발생 여부를 확인한다.
- 브라우저에서 새 게임을 여러 번 눌러 보드가 정상 표시되는지 확인한다.

## 9. 구현 후 문서화 항목

- 적용한 밸런스 규칙은 `6/8 인접 방지`까지임을 명시한다.
- 공식 대회 세팅 전체를 구현한 것은 아니라고 적는다.
- fallback이 존재한다면 개발자용 주석에 남긴다.

## 10. 위험 요소

- 인접 판정이 좌표나 vertex 공유 기준과 어긋나면 실제 인접과 다른 결과가 나올 수 있다.
- 제한 횟수가 너무 낮으면 fallback이 자주 발생할 수 있다.
- 생성 로직이 복잡해지면 테스트 헬퍼가 필요할 수 있다.

## 11. 롤백 방법

숫자 배치 재시도 로직을 제거하고 기존 `shuffle(numbers)` 방식으로 되돌린다.
