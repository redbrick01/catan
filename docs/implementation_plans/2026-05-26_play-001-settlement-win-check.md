# 수정 계획서: PLAY-001 마을 건설 승리 체크 누락

작성일: 2026-05-26  
관련 문제 문서: `docs/known_issues/2026-05-26_playability-issues.md`  
대상 파일: `script.js`

## 1. 목적

일반 플레이 중 마을 건설로 10점에 도달했을 때 즉시 승리 처리되도록 한다.

## 2. 현재 문제

`buildSettlement()`는 마을 건설 후 점수에 영향을 주지만 `checkWin()`을 호출하지 않는다.

현재 흐름:

- 위치와 비용 검사
- 자원 지불
- 교차점 소유자 설정
- 마을 말 차감
- 로그 기록
- 최장 교역로 갱신
- 반환

문제:

- 정식 턴에서 새 마을 건설로 10점이 되어도 `game.winner`가 즉시 설정되지 않는다.
- 초기 배치 중에는 승리 체크가 필요 없으므로 정식 플레이 건설과 구분해야 한다.

## 3. 수정 범위

- `buildSettlement()` 내부에 승리 체크를 추가한다.
- 초기 배치 단계에서는 승리 체크가 실행되지 않도록 한다.
- 기존 최장 교역로 갱신 흐름은 유지한다.

## 4. 구현 계획

1. `buildSettlement(player, vertexId, setup = false)`의 성공 처리 마지막 부분을 확인한다.
2. `updateLongestRoad()` 호출 뒤 또는 반환 직전에 `if (!setup) checkWin();`를 추가한다.
3. `setup` 단계의 시작 자원 지급과 초기 배치 진행에는 영향이 없는지 확인한다.
4. 마을 건설 후 승리하면 `game.winner`가 설정되고 버튼들이 비활성화되는 기존 흐름과 연결되는지 확인한다.

## 5. 세부 구현 체크리스트

대상 함수:

- `buildSettlement(player, vertexId, setup = false)`
- `checkWin()`
- `renderControls()`
- `guideFor()`

변경 포인트:

- `vertices[vertexId].owner = player.id` 이후 실제 점수 상태가 바뀐다.
- `updateLongestRoad()`는 도로 보너스 재계산용이므로 기존 위치를 유지한다.
- `checkWin()`은 `setup === false`일 때만 호출한다.
- `checkWin()` 호출 뒤 별도 `render()` 호출을 추가할지는 기존 호출 흐름을 확인한 뒤 결정한다. 현재 건설 함수들은 이벤트 핸들러 이후 전체 `render()`가 호출되는 구조라면 중복 렌더링을 피한다.

권장 코드 위치:

```js
updateLongestRoad();
if (!setup) checkWin();
return true;
```

수정하지 않을 것:

- `canBuildSettlement()`의 거리 규칙
- 마을 비용 `COSTS.settlement`
- 초기 배치 순서 `setupStepComplete()`
- 시작 자원 지급 `grantInitialResources()`

## 6. 테스트 시나리오

### TC-001: 9점 플레이어가 마을 건설로 승리

사전 조건:

- 게임 단계는 `play`
- 현재 플레이어는 9점
- 현재 플레이어는 마을 말이 1개 이상 남아 있음
- 현재 플레이어는 마을 비용 자원을 보유
- 건설 가능한 교차점과 연결 도로가 있음
- `game.rolled === true`

절차:

1. 마을 건설 행동을 선택한다.
2. 합법 위치에 마을을 놓는다.
3. 로그와 `game.winner`를 확인한다.

기대 결과:

- 마을이 놓인다.
- 현재 플레이어의 점수가 10점 이상이 된다.
- `game.winner === currentPlayer().id`
- 승리 로그가 1회 기록된다.
- 이후 주요 행동 버튼이 비활성화된다.

### TC-002: 초기 배치 마을은 승리 체크를 하지 않음

사전 조건:

- 게임 단계는 `setup1` 또는 `setup2`
- 현재 플레이어가 초기 마을을 놓을 차례

절차:

1. 초기 마을을 놓는다.
2. 초기 도로를 놓는다.
3. 다음 플레이어 또는 다음 초기 배치 단계로 넘어가는지 확인한다.

기대 결과:

- `game.winner`는 `null`이다.
- 초기 배치 흐름은 기존과 동일하다.

### TC-003: 9점 미만 마을 건설은 승리하지 않음

사전 조건:

- 현재 플레이어는 8점 이하
- 정식 플레이 중 마을 건설 가능

기대 결과:

- 마을 건설은 성공한다.
- `game.winner`는 `null`이다.

## 7. 테스트 상태 구성 메모

현재 `installTestHelpers()`가 `?test=1`에서 노출된다면 다음 보조 기능을 활용한다.

- 플레이어 자원 지급
- 보드 상태 조회
- 특정 vertex/edge 소유 상태 구성
- 플레이 단계와 주사위 상태 강제 구성

부족하면 이 이슈와 별도로 테스트 헬퍼에 다음 기능을 추가하는 것을 고려한다.

- `setPointsFixture(playerId, publicPoints)`
- `placeOwnedRoad(playerId, edgeId)`
- `setPhase("play")`

## 8. 완료 기준

- 9점 플레이어가 마을을 지어 10점이 되면 즉시 승리 로그가 남는다.
- `game.winner`가 현재 플레이어 id로 설정된다.
- 초기 배치 중 마을 배치에서는 승리 체크가 실행되지 않는다.
- 기존 도시 업그레이드와 도로 건설 승리 체크는 변하지 않는다.

## 9. 검증 방법

- `node --check script.js`
- 테스트 헬퍼 또는 브라우저 콘솔로 9점 상태를 구성한다.
- 정식 플레이 단계에서 마을을 건설한다.
- 로그에 `승리! 10점 달성.`이 기록되는지 확인한다.
- 새 게임 후 초기 배치가 기존처럼 완료되는지 확인한다.

## 10. 위험 요소

- `checkWin()`은 현재 플레이어 기준으로 동작하므로, 호출 시점의 `game.active`가 건설한 플레이어와 일치해야 한다.
- 초기 배치에서 잘못 호출하면 게임 시작 전 승리 상태가 생길 수 있다.

## 11. 롤백 방법

추가한 `checkWin()` 호출만 제거하면 이전 동작으로 돌아간다.
