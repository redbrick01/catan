# 요청 기반 UI/흐름 수정 구현 계획서

작성일: 2026-05-27

## 목적

봇 포함 온라인 플레이 중 사용자가 직접 발견한 불편 사항을 계획서-수정-보고서 절차 없이 즉시 개선한 항목들을 하나의 구현 계획으로 정리한다.

이 문서는 신규 기능 대형 단계 계획이 아니라, 실제 플레이 중 발생한 UI/알림/진행 흐름 문제를 빠르게 고치는 보수 계획이다.

## 범위

포함:

- 7 규칙 카드 버리기 모달 UI 개선
- 약탈 대상 선택 모달 UI 개선
- 봇 행동 템포 완화
- `start-katan.cmd`로 켠 서버를 끄기 위한 종료 스크립트 추가
- 봇/다른 유저 행동 알림 모달 추가
- 7 약탈 결과 모달이 즉시 사라지는 문제 수정
- 플레이어 교환 중 턴 넘기기 비활성 사유 개선
- 은행/항구 교환 알림에 실제 교환 자원 표시

제외:

- 봇 의사결정 고도화
- 플레이어 교환 규칙 자체 변경
- 은행/항구 교환 비율 규칙 변경
- 전체 UI 디자인 시스템 재작성
- 장기 운영/배포 자동화

## 구현 원칙

1. 기존 서버 command 검증 흐름은 유지한다.
2. 규칙 변경이 아니라 사용자가 이해하기 어려운 상태 표시를 개선한다.
3. 중요한 입력 모달은 행동 알림보다 우선한다.
4. 결과 알림은 사용자가 확인할 때까지 유지한다.
5. 봇 테스트 속도는 유지하고 실제 플레이 템포만 늦춘다.
6. 모달 UI 변경은 전용 클래스로 분리해 기존 거래/일반 모달에 영향을 줄인다.

## 피드백 및 반영 방향

### 피드백 1. 사후 계획서 성격이 더 명확해야 한다

문제:

- 이 문서는 이미 사용자의 단건 요청으로 수정한 내용을 정리하는 계획서다.
- 일반적인 사전 구현 계획처럼 읽히면 실제 작업 흐름과 다르게 해석될 수 있다.

반영:

- 각 항목은 "신규 설계"가 아니라 "요청 기반 보수 작업"으로 본다.
- 구현 계획은 앞으로 같은 문제를 다시 추적하거나 검증할 때 사용할 기준으로 작성한다.
- 완료 기준은 이미 적용한 수정이 의도대로 동작하는지 확인하는 회귀 기준으로 둔다.

### 피드백 2. 알림 모달 우선순위가 더 구체적이어야 한다

문제:

- 행동 알림을 모두 모달로 띄우면 카드 버리기, 약탈 대상 선택, 플레이어 교환 응답 같은 중요한 입력을 가릴 수 있다.

반영:

- 입력이 필요한 pending 모달을 최우선으로 둔다.
- 행동 알림은 `noticeQueue`에 쌓고, 현재 모달이 닫힌 뒤 순서대로 표시한다.
- 방 종료, 재접속 대기, 방 나가기 확인 모달은 행동 알림보다 우선한다.

### 피드백 3. 은행/항구 교환 상세 공개 범위를 명시해야 한다

문제:

- `lastTrade.give/get` 공개는 다른 플레이어에게 교환 자원 종류를 보여주는 변경이다.
- 은행/항구 교환은 공개 행동으로 보는 것이 자연스럽지만, 문서에 전제가 없으면 정보 공개 변경으로 보일 수 있다.

반영:

- 은행/항구 교환의 `give`, `get`, `ratio`는 공개 행동 결과로 취급한다.
- 손패 전체나 비공개 개발 카드 정보는 공개하지 않는다.
- `lastTrade`는 마지막 은행/항구 교환 결과만 표시하며 장기 히스토리 저장 목적은 아니다.

### 피드백 4. 서버 재시작 필요성이 검증 절차에 포함되어야 한다

문제:

- `server.js` 변경은 이미 켜진 Node 프로세스에는 반영되지 않는다.
- 사용자가 기존 서버를 계속 켜둔 상태면 은행/항구 교환 알림이 이전 문구로 보일 수 있다.

반영:

- 수동 검증 전에 `stop-katan.cmd` 실행 후 `start-katan.cmd`로 재시작한다.
- 은행/항구 교환 문구 검증은 재시작 이후에만 완료로 판단한다.

### 피드백 5. 플레이어 교환 차단은 오류가 아니라 규칙임을 더 분리해야 한다

문제:

- 플레이어 교환 pending 중 턴 넘기기가 비활성화되는 것은 서버 규칙상 정상이다.
- 실제 수정 대상은 차단 자체가 아니라 차단 사유 표시다.

반영:

- 서버의 `pendingPlayerTrade` 차단 규칙은 유지한다.
- 클라이언트 안내 문구만 구체화한다.
- 향후 규칙 변경이 필요하면 별도 계획으로 분리한다.

## 구현 계획

### 1. 카드 버리기 모달 UI 개선

대상 파일:

- `script.js`
- `styles.css`

계획:

- 온라인 7 규칙 카드 버리기 모달에 전용 구조를 추가한다.
- 선택 수량을 `현재/필요` 형태로 표시한다.
- 진행률 바를 추가해 남은 선택량을 시각적으로 보여준다.
- 각 자원 행에 자원명, 아이콘, 보유량, 선택 수량, +/- 버튼을 배치한다.
- 필요한 수량을 정확히 선택했을 때만 `선택 완료` 버튼을 활성화한다.
- 모바일 화면에서 행과 버튼 크기가 무너지지 않도록 보정한다.

완료 기준:

- 자원 선택 상태가 즉시 반영된다.
- 필요한 수량보다 많이 선택할 수 없다.
- 보유량보다 많이 선택할 수 없다.
- 선택 완료 전에는 제출할 수 없다.

### 2. 약탈 대상 선택 모달 UI 개선

대상 파일:

- `script.js`
- `styles.css`

계획:

- 약탈 대상 선택 목록을 단순 버튼에서 카드형 선택지로 변경한다.
- 각 대상 카드에 플레이어 이름, 보유 자원 수, 무작위 자원 1장 안내를 표시한다.
- 클릭 후 모든 대상 버튼을 비활성화해 중복 요청을 막는다.
- 대상 목록이 비어 있는 비정상/갱신 중 상태에 안내 메시지를 표시한다.
- hover, focus, disabled 상태 스타일을 추가한다.

완료 기준:

- 대상이 2명 이상일 때 선택지가 명확히 구분된다.
- 선택 요청 중 같은 command가 중복 전송되지 않는다.
- 대상 없음 상태에서도 빈 모달만 보이지 않는다.

### 3. 봇 진행 속도 완화

대상 파일:

- `server.js`

계획:

- 봇 runner 기본 지연 시간을 실제 플레이 기준 `350ms`에서 `900ms`로 늘린다.
- `NODE_ENV=test`에서는 기존처럼 지연을 `0ms`로 유지한다.
- `BOT_RUNNER_DELAY_MS` 환경변수로 실제 플레이 지연 시간을 조정할 수 있게 한다.

완료 기준:

- 실제 플레이에서 봇 행동을 눈으로 따라갈 수 있다.
- 자동 테스트 실행 시간은 늘어나지 않는다.
- 환경변수로 지연 시간을 조정할 수 있다.

### 4. 서버 종료 스크립트 추가

대상 파일:

- `stop-katan.cmd`
- `stop-katan.js`

계획:

- `start-katan.cmd`와 짝이 되는 종료 스크립트를 추가한다.
- 기본 포트 `4173`에서 LISTEN 중인 프로세스를 찾아 종료한다.
- `PORT` 환경변수가 있으면 해당 포트를 기준으로 종료한다.
- 서버가 실행 중이 아니면 안전하게 안내만 출력한다.

완료 기준:

- 사용자가 더블클릭 또는 `.\stop-katan.cmd`로 서버를 종료할 수 있다.
- 다른 포트로 실행한 경우에도 `PORT`를 맞추면 종료할 수 있다.

### 5. 다른 유저/봇 행동 알림 모달 추가

대상 파일:

- `script.js`

계획:

- 온라인 state 변경을 비교해 다른 플레이어의 공개 행동을 감지한다.
- 감지 대상은 도로 건설, 마을 건설, 도시 업그레이드, 개발 카드 구입, 은행/항구 교환으로 한다.
- 알림은 큐에 쌓고, 사용자가 `확인`을 누를 때까지 유지한다.
- 강도 처리, 카드 버리기, 플레이어 교환 응답 같은 입력 모달이 떠 있으면 알림은 나중에 표시한다.
- 내 행동에 대해서는 같은 알림을 띄우지 않는다.

완료 기준:

- 봇 행동 알림이 너무 빨리 사라지지 않는다.
- 중요한 입력 모달이 행동 알림에 덮이지 않는다.
- 여러 알림이 연속 발생하면 순서대로 확인할 수 있다.
- 방 종료/재접속 대기/방 나가기 확인 모달은 행동 알림보다 우선한다.

### 6. 7 약탈 결과 모달 자동 닫힘 수정

대상 파일:

- `script.js`

문제:

- 약탈 대상 선택 후 서버 state가 먼저 도착해 `도둑 결과` 모달을 띄운다.
- 이후 기존 클릭 핸들러의 `hideModal()`이 실행되면서 결과 모달까지 닫는다.

계획:

- 약탈 대상 선택 시 클릭 당시의 `modalKind`를 저장한다.
- command 완료 후 현재 모달이 여전히 기존 선택 모달일 때만 닫는다.
- 이미 결과 모달이나 다음 단계 모달로 바뀌었으면 닫지 않는다.
- 카드 버리기 완료 후 다음 모달이 닫힐 수 있는 같은 패턴도 함께 수정한다.

완료 기준:

- 내가 7을 굴려 약탈한 뒤 도둑 결과 모달이 유지된다.
- 결과 모달은 사용자가 `확인`을 눌러야 닫힌다.

### 7. 플레이어 교환 중 턴 넘기기 사유 개선

대상 파일:

- `script.js`

계획:

- `onlineTurnBlockedMessage("endTurn")`에서 `pendingPlayerTrade`를 별도 처리한다.
- 플레이어 교환이 진행 중이면 일반 안내 대신 다음 문구를 표시한다.

```text
진행 중인 플레이어 교환을 먼저 취소하거나 확정하세요.
```

완료 기준:

- 교환 요청 후 턴 넘기기가 막혔을 때 이유가 명확히 표시된다.
- 서버의 pending trade 차단 규칙은 그대로 유지된다.
- 이 항목은 턴 넘기기를 허용하는 변경이 아니라 차단 사유를 명확히 하는 변경이다.

### 8. 은행/항구 교환 알림 상세화

대상 파일:

- `server.js`
- `script.js`

문제:

- 기존 알림은 `보유 자원 6장 -> 3장`처럼 총량 변화만 보여줘 실제로 무엇을 냈고 받았는지 알 수 없다.

계획:

- 서버의 `lastTrade`에 `seatIndex`, `ratio`, `give`, `get`, `createdAt`을 저장한다.
- public match state에 `lastTrade` view를 명시적으로 포함한다.
- 클라이언트가 `lastTrade.give/get`을 받아 `목재 4장 -> 벽돌 1장` 형태로 표시한다.
- `give/get` 정보가 없으면 애매한 은행/항구 교환 알림은 띄우지 않는다.
- 실행 중인 서버가 이전 코드일 수 있으므로 재시작 필요성을 안내한다.
- 공개 범위는 마지막 은행/항구 교환 결과의 자원 종류와 비율로 한정한다.
- 손패 전체, 개발 카드, 교환 후보 평가는 공개하지 않는다.

완료 기준:

- 은행/항구 교환 알림에 낸 자원과 받은 자원이 표시된다.
- 단순 총량 변화만 있는 알림은 더 이상 표시하지 않는다.
- 서버 재시작 후 실제 플레이에서 새 문구가 표시된다.

## 검증 계획

정적 검증:

```powershell
node --check server.js
node --check script.js
node --check stop-katan.js
```

회귀 테스트:

```powershell
node scripts\bot-08-ui-logging-regression-test.js
node scripts\bot-09-stabilization-regression-test.js
node scripts\online-12-robber-seven-pending-ws-test.js
```

수동 확인:

- `stop-katan.cmd`로 기존 서버 종료
- `start-katan.cmd`로 서버 시작
- 봇 2명 이상 추가 후 게임 시작
- 봇 턴 진행 속도가 이전보다 느린지 확인
- 7이 나온 뒤 카드 버리기/강도 이동/약탈 대상 선택 모달 확인
- 약탈 결과 모달이 자동으로 사라지지 않는지 확인
- 봇이 건설/개발 카드 구입/은행 교환 시 알림이 확인 버튼 전까지 유지되는지 확인
- 은행/항구 교환 알림에 `낸 자원 N장 -> 받은 자원 1장`이 표시되는지 확인
- 플레이어 교환 요청 중 턴 넘기기를 눌렀을 때 정확한 안내가 나오는지 확인
- `stop-katan.cmd`로 서버가 종료되는지 확인

## 위험 요소

- 행동 알림 감지가 public state 차이를 기반으로 하므로, 같은 revision에서 여러 변화가 겹치면 알림이 여러 개 쌓일 수 있다.
- 은행/항구 교환 알림은 `lastTrade`가 최신 state에 있어야 정확히 표시된다.
- 실행 중인 서버를 재시작하지 않으면 서버 측 변경이 반영되지 않는다.
- 결과 모달을 유지하는 변경은 기존 자동 닫힘 흐름과 충돌할 수 있어 pending/trade 모달 우선순위를 계속 확인해야 한다.
- 은행/항구 교환의 `give/get` 공개는 공개 행동 결과라는 전제에 의존한다.
- 브라우저에 이전 `script.js`가 캐시되어 있으면 새 클라이언트 문구가 즉시 보이지 않을 수 있다. 이 경우 새로고침 후 확인한다.

## 완료 기준

- 사용자가 봇 진행과 다른 플레이어 행동을 모달로 확인할 수 있다.
- 카드 버리기와 약탈 대상 선택 모달이 읽기 쉽고 조작하기 쉽다.
- 7 약탈 결과가 자동으로 사라지지 않는다.
- 플레이어 교환 중 막힌 이유가 명확히 표시된다.
- 은행/항구 교환 알림이 실제 교환 자원을 표시한다.
- 서버 시작/종료가 각각 `start-katan.cmd`, `stop-katan.cmd`로 가능하다.
