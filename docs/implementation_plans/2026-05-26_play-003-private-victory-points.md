# 수정 계획서: PLAY-003 승점 카드 비공개 처리

작성일: 2026-05-26  
관련 문제 문서: `docs/known_issues/2026-05-26_playability-issues.md`  
대상 파일: `script.js`, `index.html`, `styles.css`

## 1. 목적

승점 개발 카드를 상대에게 공개하지 않고, 현재 플레이어에게만 자신의 실제 점수 또는 숨은 승점 정보를 보여준다.

## 2. 현재 문제

`visiblePoints(player)`가 승점 개발 카드를 항상 포함한다.

현재 UI 영향:

- 좌석 UI의 점수가 승점 카드를 포함해 표시된다.
- 플레이어 목록의 점수도 승점 카드를 포함한다.
- 개발 카드 개수는 공개되지만, 승점 카드가 점수에 반영되어 사실상 공개된다.

## 3. 수정 방향

점수 계산을 두 종류로 분리한다.

- 공개 점수: 마을, 도시, 최장 교역로, 최대 기사력
- 실제 점수: 공개 점수 + 승점 개발 카드

권장 함수:

- `publicPoints(player)`
- `totalPoints(player)`

기존 `visiblePoints()`는 혼동을 줄이기 위해 역할을 바꾸거나 제거한다.

## 4. UI 정책

- 상대 플레이어 카드에는 공개 점수만 표시한다.
- 현재 플레이어 카드에는 공개 점수와 숨은 승점 수를 함께 표시한다.
- 승리 체크는 반드시 실제 점수 기준으로 한다.

표시 예:

- 현재 플레이어: `9점 (+숨은 1)`
- 상대 플레이어: `8점`

## 5. 구조 변경 여부

이 계획의 1차 수정은 전체 구조 변경 없이 진행한다.

1차 범위:

- 점수 계산 함수를 공개 점수와 실제 점수로 분리한다.
- 현재 플레이어 기준으로 UI 표시를 다르게 한다.
- 승리 판정은 실제 점수를 사용한다.

전체 구조 변경이 필요한 범위:

- 플레이어별 로그인 또는 세션을 둔다.
- 각 플레이어가 자기 화면에서만 자기 승점 카드를 볼 수 있게 한다.
- 서버가 비밀 정보를 보관하고 클라이언트에는 공개 정보만 내려준다.
- 핫시트에서 턴 전환 전 가림 화면을 강제해 이전 플레이어 손패가 보이지 않게 한다.

따라서 이번 계획은 "화면 표시 정책 개선"이며, 보안적 의미의 비공개 정보 보호는 별도 대형 작업으로 분리한다.

## 6. 구현 계획

1. `visiblePoints(player)`를 `publicPoints(player)`와 `totalPoints(player)`로 분리한다.
2. `checkWin()`은 `totalPoints(currentPlayer()) >= 10`을 사용한다.
3. `renderSeats()`에서 현재 플레이어와 상대 플레이어 표시를 분기한다.
4. `renderPlayers()`에서도 같은 정책을 적용한다.
5. `installTestHelpers()`의 상태 반환값도 공개 점수와 실제 점수를 구분할지 결정한다.
6. 현재 플레이어 개발 카드 패널에는 승점 카드 수를 유지하되, 상대에게 보이는 영역에는 종류가 드러나지 않게 한다.

## 7. 세부 구현 체크리스트

대상 함수:

- `visiblePoints(player)`
- 새 함수 `publicPoints(player)`
- 새 함수 `hiddenVictoryPoints(player)`
- 새 함수 `totalPoints(player)`
- `checkWin()`
- `renderSeats()`
- `renderPlayers()`
- `renderTurnStage()`
- `installTestHelpers()`

권장 계산 분리:

```js
function publicPoints(player) {
  let points = vertices
    .filter((v) => v.owner === player.id)
    .reduce((sum, v) => sum + (v.city ? 2 : 1), 0);
  if (game.largestArmy === player.id) points += 2;
  if (game.longestRoad === player.id) points += 2;
  return points;
}

function hiddenVictoryPoints(player) {
  return player.dev.filter((card) => card.type === "victory").length;
}

function totalPoints(player) {
  return publicPoints(player) + hiddenVictoryPoints(player);
}
```

호환성 처리:

- 기존 코드에서 `visiblePoints(player)`를 많이 호출한다면 즉시 제거하지 말고, 1차 수정에서는 `visiblePoints`를 `publicPoints` 별칭으로 유지한다.
- 승리 체크에는 절대 `visiblePoints`를 사용하지 않는다.
- 테스트 헬퍼 반환값은 `publicPoints`, `hiddenPoints`, `totalPoints`를 모두 제공한다.

UI 표시 정책:

| 화면 위치 | 현재 플레이어 | 상대 플레이어 |
| --- | --- | --- |
| 좌석 점수 | 실제 점수 또는 `공개 + 숨은` | 공개 점수만 |
| 플레이어 목록 | 실제 점수 또는 `공개 + 숨은` | 공개 점수만 |
| 개발 카드 수 | 총 장수와 종류 요약 가능 | 총 장수만 |
| 승리 체크 | 실제 점수 | 해당 없음 |

권장 표시 문구:

- 현재 플레이어 숨은 승점 0장: `8점`
- 현재 플레이어 숨은 승점 1장 이상: `9점 (공개 8 + 숨은 1)`
- 상대 플레이어: `8점 공개`

CSS 고려:

- 점수 문구가 길어질 수 있으므로 `.vp` 또는 점수 영역에 줄바꿈 허용 여부를 확인한다.
- 작은 좌석 카드에서 `공개 8 + 숨은 1`이 넘치면 `9점`과 보조 텍스트를 분리한다.

## 8. 테스트 시나리오

### TC-001: 상대 승점 카드가 공개 점수에 반영되지 않음

사전 조건:

- 플레이어 1이 현재 플레이어
- 플레이어 2 공개 점수 4점
- 플레이어 2 승점 카드 2장 보유

기대 결과:

- 플레이어 2 좌석에는 `4점` 또는 `4점 공개`만 표시된다.
- 플레이어 2가 실제로는 6점이어도 현재 화면에서 숨은 점수는 드러나지 않는다.

### TC-002: 현재 플레이어는 자기 숨은 승점을 확인 가능

사전 조건:

- 플레이어 1이 현재 플레이어
- 플레이어 1 공개 점수 8점
- 플레이어 1 승점 카드 1장 보유

기대 결과:

- 플레이어 1 좌석에는 총 9점이 보인다.
- 숨은 승점 1장이 보조 정보로 표시된다.

### TC-003: 승점 카드 포함 10점 승리

사전 조건:

- 현재 플레이어 공개 점수 8점
- 승점 카드 2장 보유
- 정식 플레이 단계

절차:

1. 승리 체크가 발생하는 행동을 수행한다.
2. 또는 `checkWin()`을 테스트 헬퍼로 호출한다.

기대 결과:

- `totalPoints(player) === 10`
- `game.winner === player.id`

### TC-004: 턴 전환 시 표시 권한 변경

사전 조건:

- 플레이어 1과 2 모두 승점 카드를 가지고 있음

절차:

1. 플레이어 1 차례 화면을 확인한다.
2. 턴 종료로 플레이어 2 차례로 넘긴다.
3. 두 좌석의 점수 표시가 바뀌는지 확인한다.

기대 결과:

- 현재 플레이어의 숨은 승점만 자세히 보인다.
- 상대의 숨은 승점은 공개되지 않는다.

## 9. 완료 기준

- 상대 플레이어의 승점 개발 카드는 점수 표시로 드러나지 않는다.
- 현재 플레이어는 자신의 실제 승리 가능성을 알 수 있다.
- 승점 카드로 실제 10점이 되면 승리 처리된다.
- 개발 카드 총 장수는 기존처럼 표시할 수 있지만 카드 종류는 공개하지 않는다.

## 10. 검증 방법

- `node --check script.js`
- 현재 플레이어에게 승점 카드 1장을 부여하고 표시를 확인한다.
- 상대 플레이어에게 승점 카드 1장을 부여하고 상대 점수가 오르지 않는지 확인한다.
- 승점 카드 포함 실제 10점 상태에서 `checkWin()`이 승리 처리하는지 확인한다.
- 화면에서 현재 플레이어 변경 후 표시 권한이 바뀌는지 확인한다.

## 11. 마이그레이션 메모

수정 후 검색해야 하는 호출:

- `visiblePoints(`
- `points: visiblePoints`
- UI 문자열의 `점`

각 호출의 새 기준:

- 승리 판정: `totalPoints`
- 상대 표시: `publicPoints`
- 현재 플레이어 표시: `totalPoints`와 `hiddenVictoryPoints`
- 테스트 상태 반환: 세 값을 모두 노출

## 12. 위험 요소

- 기존 테스트 헬퍼와 문서에서 `visiblePoints` 이름을 전제로 할 수 있다.
- 승리 체크가 공개 점수를 사용하면 승점 카드 승리가 누락된다.
- 현재 플레이어 기준 표시가 핫시트 화면 공유 환경에서는 완전한 비공개를 보장하지 않는다.

## 13. 롤백 방법

점수 계산 함수를 기존 `visiblePoints()` 단일 구조로 되돌리고 UI 분기를 제거한다.
