# 봇 08 UI 및 로그 계획

작성일: 2026-05-26

## 목적

봇 기능이 사람 플레이어에게 명확하게 보이도록 로비, 플레이어 카드, 버튼 상태, 로그 표시를 정리한다.

## 2차 꼼꼼 피드백 요약

```text
1. UI는 public state에만 의존하므로 server.js의 publicPlayer/makePlayerView에 isBot을 안전하게 노출해야 한다.
2. 봇을 "연결됨"으로 표시하면 사람 접속 상태와 혼동되므로 로비에서는 "봇" 또는 "준비됨"으로 별도 표시해야 한다.
3. 봇 턴 disabled보다 사람 pending UI가 우선해야 하며, discard/robber/trade 응답 모달이 막히면 안 된다.
4. 봇 처리 중 표시는 내부 평가 점수나 전략 설명 없이 짧은 상태 텍스트로 제한해야 한다.
5. 전역 로그는 공개 행동 결과만 보여주고 훔친 자원/개발 카드 타입/판단 근거는 절대 노출하지 않아야 한다.
6. 봇 add/remove UI는 host+lobby에서만 보여야 하며 playing 중에는 숨겨야 한다.
7. 모바일 검증은 단순 화면 폭뿐 아니라 긴 이름, 봇 배지, 제거 버튼, 거래/pending 모달까지 포함해야 한다.
```

## 범위

포함:

```text
로비 봇 표시
게임 중 봇 배지
봇 턴 중 버튼 비활성화
봇 행동 로그
비공개 정보 로그 점검
봇 턴과 사람 pending 응답 UI의 우선순위 정리
모바일/데스크톱 브라우저 화면 검증
```

제외:

```text
봇 아바타
봇 성격/난이도 UI
상세 전략 설명 UI
별도 봇 설정 화면
```

## UI 원칙

```text
봇은 사람과 같은 플레이어 카드에 표시한다.
추가 설명 페이지나 새 모드를 만들지 않는다.
방장만 로비에서 봇 추가/제거를 조작한다.
봇 행동은 로그로 이해 가능해야 한다.
비공개 정보는 로그에 노출하지 않는다.
봇 UI는 기존 사람 플레이어 UI 위에 최소한으로 얹는다.
봇 표시는 텍스트 배지와 title/aria-label을 함께 사용해 색에만 의존하지 않는다.
```

상태 노출 원칙:

```text
isBot, botDifficulty: public state에 노출 가능
bot 내부 runner 상태, 평가 점수, 선택 후보, 타이머 id: public state에 노출 금지
봇 dev card 타입, 훔친 자원 종류: 기존 개인 view 정책 외 노출 금지
```

## 표시 항목

로비:

```text
봇 이름
봇 배지
방장 전용 봇 추가/제거 버튼
현재 사람/봇 포함 참가자 수
봇 row의 상태는 "연결됨" 대신 "봇" 또는 "준비됨"
```

게임:

```text
플레이어 카드의 봇 배지
봇 턴 중 조작 불가 상태
봇 행동 로그
현재 차례 표시
봇 처리 중 상태 표시
사람 pending 응답 안내
봇이 active player인 경우 현재 차례에 "봇 처리 중" 또는 "봇 차례" 표시
```

로그 예시:

```text
봇 1: 주사위를 굴렸습니다.
봇 1: 도로를 건설했습니다.
봇 2: 강도를 이동했습니다.
봇 2: 거래를 거절했습니다.
봇 1: 개발 카드를 사용했습니다.
봇 2: 7 규칙으로 카드를 버렸습니다.
```

금지 로그:

```text
봇 1이 민수에게서 밀을 훔쳤습니다.
봇 2가 승점 카드를 보유 중입니다.
봇 1이 상대의 기사 카드를 보고 거래를 거절했습니다.
```

로그 공개 범위:

```text
전역 로그: 모든 사람이 알아도 되는 행동 결과만 표시
개인 UI/모달: 해당 플레이어에게만 허용된 정보만 표시
서버 콘솔: 디버그용 정보는 가능하지만 비공개 정보가 장기 로그로 남지 않게 주의
```

전역 로그 허용:

```text
봇 1: 주사위를 굴렸습니다.
봇 1: 강도를 이동했습니다.
봇 2: 거래에 응답했습니다.
봇 1: 개발 카드를 사용했습니다.
봇 2: 카드를 버렸습니다.
```

전역 로그 금지:

```text
봇이 훔친 자원 종류
봇이 보유한 개발 카드 종류
봇이 상대 비공개 정보를 기준으로 판단한 이유
```

권장 로그 톤:

```text
봇 행동 결과만 짧게 표시한다.
봇의 내부 점수나 판단 이유는 표시하지 않는다.
상대가 알 수 없는 자원/카드 종류는 표시하지 않는다.
```

## 구현 순서

```text
1. lobby player row의 isBot 표시
2. lobby bot add/remove 버튼 상태 정리
3. game player card의 isBot 표시
4. 봇 턴 버튼 disabled 조건 점검
5. 사람 pending 응답 UI가 봇 턴 disabled에 묻히지 않게 조건 분리
6. 봇 처리 중 상태 표시 추가
7. 봇 행동 로그 문구 정리
8. 비공개 정보 노출 로그 검색
9. 데스크톱/모바일 화면 검증
10. public state에 isBot/botDifficulty만 노출되는지 확인
11. pending/trade 모달 우선순위 회귀 확인
```


## UI 상태 규칙

```text
방장 + lobby + 빈자리 있음: 봇 추가 버튼 활성화
방장 + lobby + 봇 있음: 봇 제거 버튼 활성화
참가자: 봇 버튼 숨김 또는 disabled
playing 상태: 봇 추가/제거 버튼 미표시
봇 턴: 사람의 주요 행동 버튼 disabled
사람 pending 응답 필요: 해당 사람 응답 버튼은 활성화
봇 턴 + 사람 pending 응답 필요: pending 응답 UI가 우선
봇 처리 중: 주사위/건설/교역 버튼은 disabled, 새 게임/방 나가기 같은 비게임 명령은 기존 정책 유지
봇 관련 pending 처리 중: 사람에게 필요한 모달이 없으면 대기 안내만 표시
```

버튼 disabled 이유는 title 또는 안내 문구로 알 수 있어야 한다.

```text
봇 차례입니다.
봇이 행동을 처리하는 중입니다.
응답이 필요한 거래/버리기가 있습니다.
```

모달 우선순위:

```text
1. 방 종료/재접속 대기
2. 사람 viewer가 직접 응답해야 하는 discard/robber/victim pending
3. 사람 viewer가 직접 응답해야 하는 player trade
4. 봇 또는 다른 사람이 처리 중인 pending 대기 안내
5. 봇 턴 대기 안내
```

봇 턴 대기 안내는 사람의 필수 응답 모달을 덮어쓰지 않는다. 이미 사람이 응답해야 하는 모달이 열려 있으면 봇 처리 중 메시지는 별도 모달로 띄우지 않는다.

## 접근성/레이아웃 확인

```text
봇 배지는 텍스트가 넘치지 않아야 한다.
로비 참가자 행은 모바일에서도 줄바꿈이 자연스러워야 한다.
버튼 텍스트는 320px 폭에서도 잘리지 않아야 한다.
색만으로 봇/사람을 구분하지 않는다.
긴 봇 이름 또는 닉네임이 참가자 행을 밀어내지 않아야 한다.
로그가 빠르게 쌓여도 control panel 높이/스크롤이 깨지지 않아야 한다.
거래 응답 모달과 discard/victim 모달은 320px 폭에서 버튼이 화면 밖으로 밀리지 않아야 한다.
봇 배지와 긴 이름이 같은 줄에 있을 때 이름은 말줄임 또는 줄바꿈으로 처리한다.
```

브라우저 확인 기준:

```text
데스크톱 폭: 1280px 이상
태블릿/좁은 폭: 780px 전후
모바일 폭: 375px 및 320px
Chrome 기준 필수, 다른 브라우저는 보조
```

## 상세 구현 체크리스트

```text
[ ] lobbyPlayerCount가 사람+봇 총합을 표시한다.
[ ] 봇은 connected 뱃지를 사람처럼 오해시키지 않는다.
[ ] 봇 row에는 "연결됨/끊김" 대신 "봇/준비됨" 계열 표시를 사용한다.
[ ] publicPlayer/makePlayerView에 isBot이 노출된다.
[ ] public state에 bot runner 내부 상태가 노출되지 않는다.
[ ] 게임 중 봇 카드에 resource/dev private view 정책이 유지된다.
[ ] 봇 로그가 기존 log limit을 넘길 때 UI가 깨지지 않는다.
[ ] 모바일/데스크톱에서 버튼이 겹치지 않는다.
[ ] 사람 pending 응답 UI가 봇 턴 disabled 조건보다 우선한다.
[ ] player trade 응답 모달이 봇 턴/봇 처리 중 안내보다 우선한다.
[ ] 전역 로그와 개인 UI에 표시 가능한 정보를 구분한다.
[ ] 버튼 disabled 이유가 title/안내 문구로 드러난다.
[ ] 320px 폭에서 로비 버튼과 플레이어 행이 깨지지 않는다.
[ ] 긴 봇 이름/사람 이름이 플레이어 row와 버튼을 밀어내지 않는다.
[ ] 봇 제거 버튼은 host+lobby+해당 row가 봇일 때만 보인다.
```

## 검증 계획

```text
로비에서 봇 배지가 보인다.
방장만 봇 추가/제거를 할 수 있다.
참가자에게는 봇 추가/제거 버튼이 보이지 않거나 disabled된다.
playing 상태에서는 봇 추가/제거 버튼이 보이지 않는다.
게임 화면에서 봇 플레이어가 구분된다.
봇 턴 중 사람 조작 버튼이 비활성화된다.
사람 pending 응답은 봇 턴 중에도 필요한 경우 표시/활성화된다.
player trade 응답은 봇 처리 중에도 필요한 경우 표시/활성화된다.
봇 행동 로그가 표시된다.
비공개 개발 카드/훔친 자원 종류가 노출되지 않는다.
public state에 봇 내부 runner/timer/evaluation 정보가 노출되지 않는다.
320px/375px/780px/1280px 폭에서 레이아웃이 깨지지 않는다.
긴 이름과 봇 배지가 함께 있을 때 행 높이/버튼 배치가 깨지지 않는다.
버튼 disabled 이유가 사용자가 이해할 수 있게 표시된다.
```

## 위험 요소

```text
봇 턴 중 UI가 사람 차례처럼 보여 혼란을 줄 수 있다.
로그가 너무 빠르게 쌓여 사람이 따라가기 어려울 수 있다.
비공개 정보가 로그나 state view에 노출될 수 있다.
봇 턴 disabled 조건이 사람의 discard/trade 응답 UI까지 막을 수 있다.
모바일에서 봇 추가/제거 버튼이 로비 참가자 목록과 겹칠 수 있다.
봇을 연결된 사람처럼 표시해 reconnect/leave 의미가 헷갈릴 수 있다.
isBot 표시를 위해 public state에 과도한 내부 필드를 노출할 수 있다.
봇 처리 중 모달이 사람의 필수 응답 모달을 덮어 pending 해결을 방해할 수 있다.
긴 이름 + 봇 배지 + 제거 버튼 조합이 320px에서 overflow를 만들 수 있다.
로그가 봇 전략 설명처럼 길어져 실제 게임 이벤트를 읽기 어렵게 만들 수 있다.
```

## 롤백/복구 방법

```text
봇 UI 배지는 제거해도 isBot 데이터는 유지되게 한다.
로비 버튼은 display none으로 숨겨 사람 전용 로비로 되돌릴 수 있어야 한다.
로그 문구 변경은 게임 상태 로직과 분리한다.
봇 처리 중 안내가 문제를 만들면 모달 대신 turnStagePanel 텍스트만 남긴다.
로비 제거 버튼 레이아웃이 불안정하면 row별 버튼 대신 host 전용 단일 제거 버튼으로 축소한다.
로그 노출이 의심되면 봇 로그는 command type 기반의 일반 문구만 남긴다.
```
