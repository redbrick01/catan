## 목적

온라인 모드에서 은행 교환과 항구 교환을 서버 권위 방식으로 구현한다.

8단계까지 완료되면 온라인 방에서 초기 배치, 주사위, 자원 지급, 턴 종료, 기본 건설이 서버 기준으로 동작한다. 9단계의 목표는 플레이어가 자기 차례에 주사위를 굴린 뒤 은행/항구 교환을 할 수 있게 만들고, 교환 결과가 모든 브라우저에 동일하게 반영되도록 하는 것이다.

이 프로젝트는 친구끼리 LAN/소규모 온라인 방에서 개인적으로 쓰는 용도이므로, 배포/운영/계정/영구 저장은 고려하지 않는다. 대신 실제 여러 기기 브라우저에서 헷갈리지 않는 UX와 서버 재시작 후 새 방 테스트 가능성을 우선한다.

## 전제

```text
1~5-2단계가 완료되어 온라인 방 생성/참가/재접속/방 종료 정책이 동작한다.
6단계가 완료되어 초기 배치가 서버 기준으로 끝나고 play phase로 진입한다.
7단계가 완료되어 rollDice/endTurn이 서버 기준으로 동작한다.
8단계가 완료되어 buildRoad/buildSettlement/buildCity가 서버 기준으로 동작한다.
오프라인 모드도 같은 교환 버튼/모달 UX를 사용하되, 실제 처리는 기존 로컬 교환 로직을 사용한다.
```

```json

  "roomId": "abc123",
  "playerId": "p_1",
```

필드 규칙:

```text
give와 get은 서로 달라야 한다.

```

권장 resource id:

```text

```

## 서버 구현 계획

### 1. 공통 온라인 command 검증 재사용

8단계의 `validatePlayCommand` 또는 동등한 helper를 재사용한다.

검증 조건:

```text
room이 존재해야 한다.
room.status === "playing"이어야 한다.
room.status === "ended"이면 ROOM_ENDED로 거부한다.
요청 playerId/playerToken 인증이 성공해야 한다.
요청 플레이어가 left 상태이면 PLAYER_LEFT로 거부한다.
요청 플레이어가 connected=false이면 PLAYER_DISCONNECTED 또는 INVALID_TOKEN으로 거부한다.
다른 참가자 중 left=false이고 connected=false인 플레이어가 있으면 거부한다.
matchState가 존재해야 한다.
game.phase === "play"여야 한다.
winner가 없어야 한다.
요청자가 현재 active player여야 한다.
game.rolled === true여야 한다.
pending action이 없어야 한다.
```

교환은 8단계의 건설과 동일하게 "주사위 이후, 턴 종료 전" 행동으로 취급한다.

### 2. 자원 검증 helper 추가

추가 또는 재사용할 helper:

```text
isValidResource(resource)
getPlayerResourceCount(player, resource)
getBankResourceCount(bank, resource)
moveResourceFromPlayerToBank(player, bank, resource, amount)
moveResourceFromBankToPlayer(bank, player, resource, amount)
```

검증:

```text
give/get이 유효하지 않으면 INVALID_RESOURCE
give와 get이 같으면 SAME_RESOURCE
플레이어의 give 자원이 필요 수량보다 적으면 NOT_ENOUGH_RESOURCES
은행의 get 자원이 1보다 적으면 BANK_RESOURCE_EMPTY
```

### 3. 항구 보유 여부 계산

서버가 현재 보드 상태를 기준으로 항구 보유 여부를 계산한다.

원칙:

```text
플레이어가 소유한 settlement/city가 항구와 연결된 vertex에 있으면 해당 항구를 보유한다.
항구 보유 여부는 클라이언트가 보낸 값이 아니라 서버 board/matchState에서 계산한다.
city 여부와 관계없이 항구 효과는 동일하다.
초기 배치 또는 일반 건설로 세운 마을/도시 모두 항구 판정 대상이다.
```

구현 후보:

```text
기존 오프라인 코드에 항구 판정 함수가 있으면 서버에서 공유/이식한다.
없으면 server.js에 getPlayerHarbors(matchState, seatIndex)를 추가한다.
board.harbors 또는 harborEdges/harborVertices 같은 기존 데이터 구조를 먼저 확인한다.
항구 데이터가 edge 기반이면 해당 edge 양끝 vertex 중 플레이어 건물이 있는지 확인한다.
항구 데이터가 vertex 목록 기반이면 해당 vertex에 플레이어 건물이 있는지 확인한다.
```

항구 타입 정책:

```text
generic 또는 any 항구: 3:1
resource-specific 항구: 해당 give resource에 대해서만 2:1
항구가 없거나 give resource와 맞지 않으면 4:1
2:1과 3:1이 동시에 가능하면 2:1을 우선한다.
```

권장 helper:

```text
getTradeRatioForResource(matchState, seatIndex, giveResource)
```

반환 예:

```text
2: 특정 자원 항구 보유
3: 일반 항구 보유
4: 항구 없음
```

### 4. bankTrade 처리 순서

서버 처리 순서:

```text
1. command 공통 구조를 검증한다.
2. validatePlayCommand를 통과한다.
3. give/get resource를 검증한다.
4. ratio = getTradeRatioForResource(matchState, seatIndex, give)를 계산한다.
5. 플레이어가 give resource를 ratio개 이상 가지고 있는지 확인한다.
6. 은행이 get resource를 1개 이상 가지고 있는지 확인한다.
7. 플레이어 give resource를 ratio개 차감한다.
8. 은행 give resource를 ratio개 증가시킨다.
9. 은행 get resource를 1개 차감한다.
10. 플레이어 get resource를 1개 증가시킨다.
11. game.lastAction 또는 로그용 최소 정보가 있다면 교환 성공 정보를 기록한다.
12. room.revision += 1
13. broadcastState(room)
14. 요청자에게 command ack를 보낸다.
```

주의:

```text
교환은 턴을 넘기지 않는다.
교환은 rolled 상태를 false로 바꾸지 않는다.
교환은 추가 pending action을 만들지 않는다.
교환만으로 winner가 바뀌지는 않는다.
은행 재고가 부족하면 부분 교환하지 않고 전체 거부한다.
```

### 5. 공개/비공개 state 처리

본인 view:

```text
본인 resources 상세 수량 표시
본인 교환 후 give/get 수량 즉시 반영
가능하면 현재 적용된 ratio 표시
```

상대 view:

```text
상대 resources 상세 미노출
resourceCount만 변경
교환한 자원 종류를 상세히 노출하지 않음
```

로그/알림 정책:

```text
개인용 게임이므로 간단한 성공 메시지는 허용한다.
다만 상대에게 "숲 2장을 양 1장으로 교환"처럼 상세 자원을 보여주면 안 된다.
공개 메시지는 "플레이어가 은행/항구 교환을 했습니다" 정도로 제한한다.
본인에게는 "숲 2장 -> 밭 1장"처럼 상세 표시 가능하다.
```

## 클라이언트 구현 계획

### 1. 온라인/오프라인 공통 UX와 처리 분기

오프라인과 온라인 모두 하나의 `교환` 버튼과 하나의 은행/항구 교환 모달을 사용한다.

UX 원칙:

```text
은행 교환 버튼과 항구 교환 버튼을 분리하지 않는다.
항구 보유 여부에 따라 같은 모달 안에서 자동으로 4:1, 3:1, 2:1 규칙을 보여준다.
사용자는 좌측에서 지불 자원, 우측에서 받을 자원을 고르는 동일한 흐름을 사용한다.
온라인/오프라인의 차이는 사용자가 보는 UI가 아니라 교환을 확정하는 처리 방식에만 둔다.
```

온라인 playing 상태에서는 로컬 교환 함수를 직접 실행하지 않는다.

분기 기준:

```text
onlineSession.connected === true
onlineSession.state.status === "playing"
game.phase === "play"
```

온라인일 때:

```text
교환 버튼 클릭 -> 은행/항구 교환 공용 모달 열기
모달에서 give/get 선택 후 확인 -> sendCommand({ name: "bankTrade", give, get })
성공 결과는 서버 state broadcast로만 반영
클라이언트에서 resources/bank를 직접 수정하지 않음
```

오프라인일 때:

```text
교환 버튼 클릭 -> 은행/항구 교환 공용 모달 열기
모달에서 give/get 선택 후 확인 -> 기존 로컬 bankTrade/trade 로직 실행
성공 결과는 기존 오프라인 상태 갱신 방식으로 반영
온라인 command를 보내지 않음
```

### 2. 교환 버튼

필수:

```text
오프라인/온라인 모두에서 은행/항구 교환 버튼 1개를 표시한다.
버튼 이름은 "교환" 또는 "은행/항구 교환"처럼 의미가 분명해야 한다.
버튼 클릭 시 교환 모달을 연다.
오프라인에서는 기존 차례/주사위/게임 상태 규칙에 맞춰 버튼을 disabled 처리한다.
온라인에서는 내 차례가 아니면 버튼 disabled
온라인에서는 주사위 전이면 버튼 disabled
온라인에서는 연결 대기 모달이 떠 있으면 버튼 disabled
온라인에서는 ended/left 상태이면 버튼 disabled
winner가 있으면 버튼 disabled
```

주의:

```text
은행 교환 버튼과 항구 교환 버튼을 따로 만들지 않는다.
항구 교환도 같은 교환 버튼과 같은 모달에서 처리한다.
UI 문구에서는 항구 보유 여부에 따라 자동으로 더 좋은 비율이 적용된다는 점을 보여준다.
```

### 3. 교환 모달

은행 교환과 항구 교환은 오프라인/온라인 모두 같은 모달에서 처리한다.

모달 구조:

```text
상단: 내 항구 보유에 따른 교환 가능 규칙 표시
좌측: 내가 지불할 자원 선택 영역
우측: 교환해서 받아올 자원 선택 영역
하단: 예상 교환 요약, 교환 실행 버튼, 닫기 버튼
```

상단 규칙 표시:

```text
항구가 없으면 "현재 교환 규칙: 기본 4:1" 표시
일반 항구가 있으면 "현재 교환 규칙: 일반 항구 3:1, 그 외 4:1" 표시
특정 자원 항구가 있으면 "현재 교환 규칙: 숲 2:1, 일반 항구 3:1, 그 외 4:1"처럼 표시
여러 특정 항구가 있으면 모두 표시
2:1, 3:1, 4:1 중 현재 선택한 지불 자원에 적용되는 비율을 강조 표시
```

좌측 지불 자원 선택:

```text
forest/hill/pasture/field/mountain을 선택할 수 있다.
각 자원 카드 또는 버튼에는 내가 가진 수량을 표시한다.
선택한 자원은 시각적으로 구분한다.
현재 적용 비율보다 보유 수량이 부족한 자원은 disabled 또는 부족 표시를 한다.
```

우측 받을 자원 선택:

```text
forest/hill/pasture/field/mountain을 선택할 수 있다.
좌측에서 선택한 자원과 같은 자원은 disabled 처리한다.
은행 재고가 0인 자원은 disabled 또는 품절 표시를 한다.
선택한 자원은 시각적으로 구분한다.
```

하단 교환 요약:

```text
"숲 4개를 내고 밭 1개 받기"
"벽돌 2개를 내고 양 1개 받기"
처럼 실제 적용될 비율과 결과를 보여준다.
give/get이 모두 선택되고 자원/은행 재고가 충분할 때만 교환 실행 버튼을 활성화한다.
```

모달 동작:

```text
교환 실행 중에는 버튼을 잠시 disabled 처리해 중복 클릭을 막는다.
온라인에서는 서버 성공 응답 또는 state broadcast 후 모달을 닫거나 선택 상태를 유지할지 결정한다.
오프라인에서는 로컬 교환 성공 후 모달을 닫거나 선택 상태를 유지할지 결정한다.
권장: 성공 후 모달을 닫고 화면 상태를 갱신한다.
서버 거부 시 모달은 유지하고 거부 메시지를 표시한다.
오프라인 로컬 검증 실패 시에도 모달은 유지하고 오류 메시지를 표시한다.
닫기 버튼이나 배경 클릭으로 모달을 닫을 수 있다.
```

## 추가 고려사항

### 1. 항구 규칙 표시의 기준

```text
모달 상단의 항구 규칙은 "현재 플레이어가 실제로 보유한 항구"만 보여준다.
아직 항구 위치에 건물이 없으면 해당 항구 규칙을 보여주지 않는다.
2:1 특정 항구와 3:1 일반 항구를 동시에 보유한 경우, 선택한 지불 자원별 최적 비율을 보여준다.
특정 자원 항구는 해당 자원을 지불할 때만 2:1로 표시한다.
```

주의:

```text
보드에 존재하는 모든 항구를 나열하면 안 된다.
사용자가 보유하지 않은 항구 규칙을 보여주면 교환 가능 여부를 오해할 수 있다.
```

### 2. 모달 선택 상태 초기화

```text
모달을 처음 열 때 give/get 선택은 비워둔다.
모달을 닫았다 다시 열면 이전 선택을 유지할지 초기화할지 정책을 정한다.
권장: 닫았다 다시 열면 초기화한다.
교환 성공 후에는 선택 상태를 초기화한다.
서버 거부 또는 오프라인 검증 실패 후에는 선택 상태를 유지해 사용자가 바로 수정할 수 있게 한다.
```

### 3. 교환 가능 비율 계산 위치

```text
온라인 최종 비율 계산은 서버가 한다.
오프라인 최종 비율 계산은 기존 로컬 게임 상태 기준으로 한다.
UI의 예상 비율은 사용자 편의를 위한 표시이며, 온라인에서는 서버 응답이 최종이다.
가능하면 온라인 서버 view에 내 tradeRatios 또는 ownedHarbors 요약을 포함해 UI 중복 계산을 줄인다.
```

권장 private view 예:

```json
{
  "trade": {
    "ownedHarbors": ["generic", "forest"],
    "ratios": {
      "forest": 2,
      "hill": 3,
      "pasture": 3,
      "field": 3,
      "mountain": 3
    }
  }
}
```

상대 view에는 위 상세 정보를 넣지 않는다.

### 4. 은행 재고 표시

```text
받을 자원 선택 영역에는 은행 재고가 0인 자원을 품절/비활성으로 표시한다.
은행 재고 수량을 전체 공개할지는 기존 UI 정책을 따른다.
개인용 게임에서는 은행 재고 공개가 큰 문제는 아니지만, 표시 방식은 오프라인/온라인이 동일해야 한다.
```

### 5. 중복 클릭과 순서 보장

```text
교환 실행 버튼을 누르면 응답 전까지 버튼을 disabled 처리한다.
같은 requestId가 중복 처리되지 않도록 기존 command 처리 방식과 맞춘다.
응답이 늦어도 클라이언트가 임의로 자원을 먼저 바꾸지 않는다.
온라인에서 교환 직후 턴 종료를 빠르게 누르는 경우에도 서버 revision 기준으로 순서가 보장되어야 한다.
```

### 6. 새로고침/재접속 중 모달 처리

```text
온라인에서 교환 모달이 열린 상태로 새로고침하면, 복구 후 모달은 닫힌 상태로 시작해도 된다.
재접속 대기 모달이 뜨면 교환 모달은 닫거나 교환 실행 버튼을 비활성화한다.
ended 모달이 뜨면 교환 모달은 닫는다.
```

```text
기존에 따로 존재하던 은행 교환 UI나 항구 교환 UI가 있다면 새 공용 모달과 중복되지 않게 정리한다.
```

```text
대응: 기존 보드 생성 데이터 구조를 먼저 확인하고, 서버/클라이언트가 같은 board state를 기준으로 판정하게 한다.

UI의 예상 비율과 서버 비율이 달라질 수 있다.
대응: 가능하면 서버 view에 tradeRatios를 포함하고 UI는 그 값을 우선 사용한다.

은행 재고와 플레이어 자원이 음수가 될 수 있다.
대응: 자원 이동 전에 모든 검증을 끝내고, 실패 시 아무 상태도 변경하지 않는다.

상대 자원 상세가 로그나 broadcast로 노출될 수 있다.
대응: public action message에는 상세 give/get을 넣지 않고, 상세는 요청자 view 또는 로컬 메시지에만 둔다.

항구 fixture 만들기가 번거로워 자동 테스트가 4:1만 커버할 수 있다.
대응: 테스트용 matchState를 직접 구성해서 3:1, 2:1 항구 vertex를 고정한다.
```
