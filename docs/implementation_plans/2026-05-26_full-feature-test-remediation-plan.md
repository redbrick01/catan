# 전체 기능 테스트 보고서 기반 수정 계획서

작성일: 2026-05-26  
기준 보고서: `docs/test_plans/2026-05-26_full-feature-test-run-report.md`  
대상 파일: `script.js`, `styles.css`, `docs/test_plans/2026-05-26_full-feature-test-run-report.md`

## 1. 목적

전체 기능 테스트 실행 보고서에서 확인된 결함과 미검증 항목을 실제 수정 가능한 작업 단위로 나누고, 각 작업의 완료 기준과 재검증 방법을 정의한다.

수정 목표:

- 기사 카드 사용 후 도둑 이동 강제 처리 상태를 UI와 버튼 상태에 정확히 반영한다.
- 플레이어 간 교환 수정 사항이 보고서와 테스트 계획에 일관되게 반영되도록 정리한다.
- 장기 플레이가 필요한 미실행 테스트를 반복 가능하게 만들기 위한 테스트 상태 구성 방안을 마련한다.
- 미실행 항목을 단계적으로 실제 검증 가능한 항목으로 전환한다.
- 게임판과 플레이어 카드/자원 정보가 스크롤 없이 한 화면에서 보이도록 레이아웃을 개선한다.
- 주사위 결과에 해당하는 생산 타일을 눈에 띄게 강조해 자원 생산 위치를 즉시 인지할 수 있게 한다.
- 주사위는 실제 게임처럼 2개의 개별 결과와 합계를 함께 표시한다.

- 도로 건설 비용 차감과 은행 반환
- 새 게임과 리셋

### 2.2 남은 확정 결함

- BUG-001: 기사 카드로 도둑 이동 시작 시 안내 문구가 도둑 이동을 표시하지 않음
- BUG-002: 기사 카드로 도둑 이동 중 주사위 버튼이 활성화됨

### 2.4 미실행 검증 항목

- 일반 플레이 중 마을 건설
- 도시 업그레이드
- 도로 건설 카드
- 풍년 카드
- 독점 카드
- 승점 카드 비공개 점수 처리
- 8장 이상 보유자의 7 카드 버리기 모달
- 은행 재고 부족 생산 규칙
- 항구 3:1, 특정 자원 2:1 실제 교환 성공
- 최장 교역로 동률/차단/탈환
- 최대 기사력 동률/탈환
- 10점 승리 전체 흐름

### 2.5 추가 UI 개선 요청

- 현재 게임판 화면에서 플레이어 3의 카드/자원 내역을 보려면 세로 스크롤이 필요하다.
- 카탄은 보드, 현재 플레이어 상태, 상대 플레이어 자원/카드 요약을 동시에 보면서 판단해야 하므로, 기본 데스크톱 화면에서는 게임판과 플레이어 정보가 한 화면에 들어와야 한다.
- 수정 목표는 플레이 중 핵심 정보 확인을 위해 페이지 스크롤이 필요하지 않게 만드는 것이다.
- 비용표는 우측 패널 내부가 아니라 보드 우측 상단에 작은 참조 카드로 떠 있어야 한다.
- 주사위를 굴렸을 때 나온 숫자에 해당하는 지형 타일은 시각적으로 강조되어야 한다.
- 주사위 UI는 단일 합계 숫자만 표시하지 않고, 주사위 2개 눈과 합계를 함께 보여야 한다.

## 4. 상세 수정 계획

### 4.1 BUG-001: 기사 카드 후 도둑 이동 안내 우선순위 수정

대상 함수:

- `guideFor()` in `script.js`

현재 문제:

- `guideFor()`가 `!game.rolled` 조건을 먼저 검사한다.
- 주사위 전 기사 카드를 사용해 `selectedAction = "robber"`가 되어도 안내가 `주사위 또는 개발 카드`로 표시된다.

수정 방향:

- `selectedAction` 기반 강제 처리 안내를 `!game.rolled`보다 먼저 평가한다.
- 우선순위는 다음 순서로 정리한다.
  - 게임 미시작
  - 게임 종료
  - 초기 배치
  - 카드 버리기
  - 도둑 이동
  - 약탈 대상 선택
  - 도로 건설 카드
  - 주사위 전 안내
  - 건설/교환 안내

완료 기준:

- 주사위 전 기사 카드 사용 직후 턴 상태 패널이 `도둑 이동`을 표시한다.
- 로그와 안내 문구가 서로 모순되지 않는다.

### 4.2 BUG-002: 강제 처리 상태 중 주사위 버튼 비활성화

대상 함수:

- `renderControls()` in `script.js`

현재 문제:

- `rollButton.disabled` 조건에 `isResolvingForcedAction()`이 빠져 있다.
- 도둑 이동 중 주사위 버튼이 활성화될 수 있다.

수정 방향:

- `rollButton.disabled` 조건에 `isResolvingForcedAction()`을 추가한다.
- 도로 건설 카드 처리 중에도 이미 `isBusyWithCardAction()`으로 차단되는지 재확인한다.
- `endTurnButton.disabled`와 행동 버튼 차단 조건도 강제 처리 상태와 일관되는지 재확인한다.

완료 기준:

- 도둑 이동, 약탈 대상 선택, 카드 버리기 중 주사위 버튼이 비활성화된다.
- 강제 처리 완료 후 주사위 전 상태라면 주사위 버튼이 다시 활성화된다.
- 주사위 후 도둑 이동 처리 완료 시 건설/교환 단계로 정상 복귀한다.

### 4.3 플레이어 교환 문서 정합성 정리

대상 문서:

- `docs/test_plans/2026-05-26_full-feature-test-run-report.md`

현재 문제:

- BUG-003은 `Fixed, Verified`로 표시되어 있으나, 보고서 상단 전체 판단 문단에는 이전 실패 내용이 일부 남아 있다.

수정 방향:

- 전체 판단 문단에서 플레이어 간 교환 불합격 표현을 제거한다.
- 교역 결과를 `부분 통과`로 유지하되, 이유를 은행/항구 실제 교환 미검증으로 명확히 바꾼다.
- TC-019와 BUG-003의 상태가 서로 모순되지 않게 정리한다.

완료 기준:

- 보고서 요약, TC 표, BUG-003 상태가 모두 동일한 현재 상태를 설명한다.

### 4.4 테스트 상태 주입 기반 추가

대상:

- `script.js`
- 필요 시 별도 테스트 스크립트 또는 브라우저 자동화용 헬퍼 문서

문제:

- 미실행 항목 대부분은 무작위 보드, 무작위 주사위, 무작위 개발 카드 더미 때문에 매번 상태를 만들기 어렵다.

수정 방향:

- 운영 UI에는 노출하지 않는 테스트 전용 헬퍼를 추가한다.
- 권장 방식:
  - URL에 `?test=1`이 있을 때만 `window.__katanTest`를 노출한다.
  - 일반 플레이에는 영향을 주지 않는다.
  - 헬퍼는 상태를 직접 조작한 뒤 반드시 `render()`를 호출한다.

권장 헬퍼:

- `setResources(playerId, resources)`
- `setBank(resources)`
- `setDevCards(playerId, cardTypes, boughtTurnOffset)`
- `setDevDeck(cardTypes)`
- `setDiceNext(total)` 또는 `forceRoll(total)`
- `setPhasePlay({ active, rolled })`
- `placeSettlement(playerId, vertexId, city)`
- `placeRoad(playerId, edgeId)`
- `setHarbor(playerId, harborType)` 또는 항구 보유 조건을 만족하는 건물 배치 헬퍼
- `getStateSummary()`

주의 사항:

- 테스트 헬퍼는 실제 사용자 플레이 경로와 분리한다.
- `?test=1`이 없으면 전역에 노출되지 않아야 한다.
- 헬퍼가 게임 규칙 함수 자체를 우회하더라도, 테스트 시나리오에서는 최종 행동을 실제 UI나 공개 함수로 수행한다.

완료 기준:

- 브라우저 자동화에서 특정 카드, 자원, 은행 재고, 보너스 상태를 1초 이내 구성할 수 있다.
- 테스트 모드가 꺼진 일반 실행에서 `window.__katanTest`가 존재하지 않는다.

### 4.5 개발 카드 전체 재검증

대상 테스트:

- TC-014 도로 건설 카드
- TC-015 풍년 카드
- TC-016 독점 카드
- TC-017 승점 카드

수정/검증 방향:

- 테스트 헬퍼로 각 카드 타입을 현재 플레이어에게 이전 턴 구매 카드로 부여한다.
- 카드 사용 목록에 승점 카드가 제외되는지 확인한다.
- 도로 건설 카드는 무료 도로 2개, 비용 미차감, 도로 말 차감을 확인한다.
- 풍년 카드는 같은 자원 2장, 서로 다른 자원 2장, 은행 재고 0/1장 조건을 확인한다.
- 독점 카드는 선택 자원이 모든 상대에게서 현재 플레이어로 이동하는지 확인한다.
- 승점 카드는 사용 없이 점수 계산에 포함되는지 확인한다.

완료 기준:

- 개발 카드 5종의 핵심 규칙이 브라우저 또는 코드 레벨 테스트로 통과한다.

### 4.6 건설과 교역 재검증

대상 테스트:

- TC-009 일반 플레이 중 마을 건설
- TC-010 도시 업그레이드
- TC-018 은행/항구 교환
- TC-020 은행 재고 부족

수정/검증 방향:

- 일반 플레이 중 마을 건설 비용 차감, 거리 규칙, 도로 연결 규칙을 검증한다.
- 도시 업그레이드 비용 차감, 말 수 변경, 점수 증가를 검증한다.
- 항구 없는 4:1, 일반 항구 3:1, 특정 자원 항구 2:1을 각각 실제 교환으로 검증한다.
- 은행 재고 부족 시 생산/교환/풍년 카드가 차단되는지 검증한다.

완료 기준:

- 자원 수량, 은행 재고, 플레이어 점수, 로그가 모두 기대값과 일치한다.

### 4.7 보너스 점수와 승리 흐름 검증

대상 테스트:

- TC-021 최장 교역로
- TC-022 최대 기사력
- TC-023 승리 판정

수정/검증 방향:

- 최장 교역로:
  - 5개 이상 단독 보유
  - 동률 시 기존 보유자 유지
  - 기존 보유자 없는 동률이면 미부여
  - 상대 건물에 의한 도로 단절
- 최대 기사력:
  - 기사 3장 이상 단독 보유
  - 동률 유지
  - 더 많은 기사 사용 시 보너스 이전
- 승리:
  - 건설로 10점
  - 승점 카드 포함 10점
  - 최장 교역로 또는 최대 기사력으로 10점

완료 기준:

- 점수 패널과 게임 종료 안내가 실제 점수 조건과 일치한다.
- 게임 종료 후 추가 행동이 차단된다.

### 4.8 게임판 한 화면 표시 레이아웃 개선

대상 파일:

- `index.html`
- `styles.css`
- 필요 시 `script.js`

현재 문제:

- 현재 화면에서는 게임판과 플레이어 좌석/카드 내역이 세로로 길어져, 플레이어 3의 카드/자원 정보를 보려면 스크롤이 필요하다.
- 보드와 플레이어 상태를 동시에 보지 못하면 교역, 건설, 도둑 약탈 판단이 불편하다.

수정 방향:

- 데스크톱 기준 첫 화면 안에 다음 요소가 모두 들어오도록 레이아웃을 재구성한다.
  - 보드 전체
  - 3~4명 플레이어 좌석 정보
  - 현재 턴/주사위 영역
  - 주요 행동 버튼이 있는 우측 패널 상단
- 비용표를 보드 우측 상단의 오버레이 카드로 이동한다.
  - 도로, 마을, 도시, 개발 카드 비용을 항상 빠르게 볼 수 있게 한다.
  - 보드 클릭을 방해하지 않도록 폭과 위치를 제한한다.
  - 필요하면 마우스 이벤트를 카드 내부에만 받도록 하고 보드 영역과 겹치는 면적을 최소화한다.
- 보드 영역은 뷰포트 높이에 맞춰 `clamp()`, `min()`, `max-height`, `aspect-ratio` 등을 사용해 안정적으로 축소한다.
- 플레이어 좌석 카드의 세로 높이를 줄이고, 자원 내역은 한 줄 또는 조밀한 그리드로 표시한다.
- 우측 패널은 전체 페이지를 늘리는 대신 자체 스크롤 영역으로 분리하고, 비용표 섹션은 우측 패널에서 제거하거나 보드 오버레이와 중복되지 않게 숨긴다.
- 페이지 전체는 데스크톱 기준 `100vh` 안에 들어오게 하고, 필요 시 우측 패널 내부만 스크롤한다.
- 모바일 화면에서는 한 화면 고정 요구보다 조작 가능성을 우선하며, 자연스러운 세로 스크롤을 허용한다.

권장 구현:

- `.app`을 데스크톱에서 `height: 100vh` 또는 `min-height: 100vh` 기반의 고정 뷰포트 레이아웃으로 조정한다.
- `.tabletop`과 `.board-area`에 `min-height: 0`을 적용해 그리드/플렉스 자식이 뷰포트를 밀어내지 않게 한다.
- `.board-wrap svg` 또는 `#board`의 최대 높이를 `calc(100vh - 상단 여백)` 안에 제한한다.
- `.board-area` 또는 `.board-wrap` 안에 비용표 오버레이 컨테이너를 배치한다.
- 비용표 카드는 `position: absolute; top: ...; right: ...;` 방식으로 보드 우측 상단에 고정한다.
- 비용표 카드의 디자인은 기존 패널보다 더 조밀하게 만들고, 배경은 보드 위에서도 읽히도록 충분한 대비를 둔다.
- 좌석 카드는 보드 주변 절대 배치가 화면을 밀어내지 않게 크기와 위치를 조정한다.
- `.control-panel`은 `max-height: calc(100vh - 여백)`와 `overflow: auto`를 적용한다.

완료 기준:

- 데스크톱 기본 뷰포트에서 페이지 세로 스크롤 없이 플레이어 1~4의 좌석 정보가 모두 보인다.
- 3인 게임에서도 플레이어 3의 카드/자원 내역이 스크롤 없이 보인다.
- 보드 전체가 잘리지 않고 육각 타일, 도둑, 도로/마을 배치 대상이 보인다.
- 비용표가 보드 우측 상단에 카드 형태로 표시된다.
- 비용표가 보드의 주요 클릭 대상, 현재 턴/주사위 영역, 플레이어 좌석 정보를 가리지 않는다.
- 우측 패널에 비용표가 중복 표시되지 않는다.
- 우측 패널 내용이 길어질 경우 페이지 전체가 아니라 우측 패널 내부만 스크롤된다.
- 작은 모바일 폭에서는 UI가 겹치지 않고 세로 스크롤이 자연스럽게 동작한다.

### 4.9 주사위 결과 타일 강조 효과 추가

대상 파일:

- `script.js`
- `styles.css`

현재 문제:

- 주사위를 굴린 뒤 로그에는 결과가 남지만, 보드에서 어떤 타일이 생산 대상인지 즉시 알아보기 어렵다.
- 특히 같은 숫자가 2개 있는 경우 두 지역을 동시에 찾아야 해서 플레이 흐름이 끊긴다.

수정 방향:

- 마지막 주사위 결과를 게임 상태에 저장한다.
  - 예: `game.lastRollTotal`
- `roll()` 또는 `produce(total)` 실행 후 해당 숫자 타일에 강조 상태를 적용한다.
- `drawTile(tile)`에서 `tile.number === game.lastRollTotal`인 타일에 강조 클래스를 부여한다.
- 7이 나온 경우에는 생산 타일 강조 대신 도둑 처리 안내를 강조하고, 일반 생산 타일 강조는 표시하지 않는다.
- 도둑이 있는 타일은 같은 숫자라도 생산이 막히므로 별도 표현을 고려한다.
  - 예: 숫자 강조는 하되 도둑 아이콘과 함께 흐린 강조
  - 또는 생산 불가 표시 클래스를 별도로 적용

권장 시각 효과:

- 타일 외곽선에 밝은 금색 강조
- 숫자 토큰 주변 펄스 또는 링 효과
- 짧은 배경 하이라이트 애니메이션
- 같은 숫자의 모든 타일을 동시에 강조
- 강조 효과는 다음 주사위가 굴려질 때 갱신된다.

주의 사항:

- 강조 효과가 도로, 마을, 도시 클릭 대상의 가시성과 상호작용을 방해하지 않아야 한다.
- 애니메이션은 과하지 않게 1~2초 안에서 안정화되도록 한다.
- 사용자가 보드를 계속 보는 동안 마지막 주사위 결과를 알 수 있도록 정적 강조 상태도 남긴다.

완료 기준:

- 주사위를 굴리면 결과 숫자와 같은 모든 타일이 즉시 강조된다.
- 숫자 6 또는 8처럼 두 타일이 존재하는 경우 두 타일이 모두 강조된다.
- 7이 나오면 생산 타일 강조가 표시되지 않고 도둑 이동 안내가 우선된다.
- 다음 주사위 결과가 나오면 이전 강조는 제거되고 새 결과 타일만 강조된다.
- 강조 효과가 보드 클릭, 도로/마을/도시 표시, 도둑 표시를 가리지 않는다.

### 4.10 주사위 2개 결과와 합계 표시

대상 파일:

- `index.html`
- `script.js`
- `styles.css`

현재 문제:

- 현재 주사위 UI는 합계만 `diceTotal`에 표시한다.
- 실제 카탄은 6면체 주사위 2개를 굴리고, 두 눈의 합으로 생산/7 처리를 한다.
- 합계만 보이면 7이 어떤 조합으로 나왔는지 알 수 없고, 실제 보드게임 감각도 약하다.

수정 방향:

- `rollDice()`가 합계 숫자만 반환하지 않고 주사위 2개의 개별 결과와 합계를 반환하도록 변경한다.
  - 예: `{ die1, die2, total }`
- 게임 상태에 마지막 주사위 결과를 저장한다.
  - 예: `game.lastDice = { die1, die2, total }`
- `roll()`은 `total`을 기준으로 기존 생산/7 처리 로직을 유지한다.
- UI에는 주사위 2개와 합계를 함께 표시한다.
  - 예: `[3] [4] 합계 7`
- 초기 상태 또는 새 턴 시작 전에는 주사위 2개가 `-`, 합계가 `-`로 표시된다.
- 로그에는 두 눈과 합계를 함께 기록한다.
  - 예: `플레이어 1: 주사위 3 + 4 = 7.`

권장 UI:

- 기존 `diceTotal` 영역을 주사위 2개 칩과 합계 텍스트로 확장한다.
- 주사위 칩은 정사각형에 가까운 형태로 만들고 숫자를 크게 표시한다.
- 합계는 보조 텍스트가 아니라 턴 판단에 중요한 값이므로 눈에 띄게 표시한다.
- 7이 나오면 합계 영역에 짧은 강조 스타일을 적용해 도둑 처리와 연결되게 한다.

주의 사항:

- 기존 테스트와 로직이 `rollDice()`의 반환값을 숫자로 가정하고 있다면 함께 수정해야 한다.
- `produce(total)`와 `startDiscardForSeven()`는 합계만 받아야 한다.
- 주사위 결과 타일 강조 기능은 `game.lastDice.total` 또는 동등한 합계 값을 기준으로 동작해야 한다.

완료 기준:

- 주사위를 굴리면 주사위 2개의 개별 값과 합계가 모두 표시된다.
- 합계는 두 주사위 값의 합과 항상 일치한다.
- 7이 나오면 `die1 + die2 = 7` 로그가 남고 도둑 처리로 진행된다.
- 2~12 결과는 합계 기준으로 기존 생산 로직과 타일 강조 효과를 정상 실행한다.
- 새 턴 또는 새 게임에서는 주사위 표시가 초기화된다.

## 5. 실행 순서

1. BUG-001과 BUG-002를 먼저 수정한다.
2. `node --check script.js`를 실행한다.
3. 브라우저에서 기사 카드 주사위 전 사용 시나리오를 재검증한다.
4. 테스트 보고서의 플레이어 교환 요약 문구를 정리한다.
5. 게임판 한 화면 표시 레이아웃을 개선하고 데스크톱/모바일 화면을 검증한다.
6. 주사위 결과 타일 강조 효과를 추가하고 생산/7 결과를 검증한다.
7. 주사위 2개 결과와 합계 표시를 구현하고 생산/7 처리와 연결해 검증한다.
8. `?test=1` 기반 테스트 헬퍼를 추가한다.
9. 개발 카드 5종 테스트를 작성하고 실행한다.
10. 건설, 은행/항구 교환, 은행 재고 부족 테스트를 작성하고 실행한다.
11. 최장 교역로, 최대 기사력, 승리 조건 테스트를 작성하고 실행한다.
12. 전체 테스트 실행 보고서를 업데이트한다.
