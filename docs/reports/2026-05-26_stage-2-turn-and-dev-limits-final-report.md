## 3. 구현 내용

### 3.1 행동 타이밍 제한 추가

`canTakePostRollAction()`을 추가해 주사위를 굴린 뒤에만 가능한 행동을 공통으로 판정하도록 했다.

대상 행동:

- 도로 건설
- 정착지 건설
- 도시 업그레이드
- 개발 카드 구매
- 은행 교환

카드 버리기, 도둑 이동, 약탈 대상 선택 중에는 위 행동이 차단된다.

### 3.2 보드 하이라이트 제한

주사위 전에는 도로, 정착지, 도시 건설 가능 하이라이트가 표시되지 않도록 했다.

초기 배치 단계에서는 기존처럼 정착지와 도로 배치가 가능하다.

### 3.3 개발 카드 데이터 구조 개선

기존 문자열 기반 개발 카드 구조를 객체 기반으로 변경했다.

변경 후 구조:

```js
{
  id: "dev-1",
  type: "knight",
  boughtTurn: 1
}
```

`game.devCardSeq`를 추가해 개발 카드 고유 id를 생성한다.

### 3.4 새로 산 개발 카드 판정 개선

기존 `player.newDev` 문자열 추적 방식을 제거했다.

이제 `boughtTurn`을 기준으로 이번 턴에 산 카드인지 판정한다.

반영된 규칙:

- 이번 턴에 산 기사 카드는 사용할 수 없다.
- 이전 턴에 산 기사 카드는 사용할 수 있다.

### 3.5 한 턴에 개발 카드 1장 사용 제한

`game.usedDevThisTurn`을 추가했다.

반영된 동작:

- 개발 카드를 사용하면 `usedDevThisTurn`이 `true`가 된다.
- 같은 턴에 추가 개발 카드 사용을 막는다.
- 턴 종료 시 `usedDevThisTurn`을 `false`로 초기화한다.

현재 구현된 사용 카드가 기사뿐이므로 이번 단계에서는 기사 카드에 제한이 적용된다. 이후 도로 건설, 풍년, 독점 카드를 추가할 때 같은 플래그를 사용하면 된다.

### 3.6 승점 카드 계산 유지

`visiblePoints()`를 새 카드 객체 구조에 맞게 수정했다.

변경 전:

```js
card === "victory"
```

변경 후:

```js
card.type === "victory"
```

## 4. 규칙 반영 내용

이번 작업은 다음 규칙을 반영했다.

- 주사위를 굴린 뒤 건설과 교역을 진행한다.
- 구입한 개발 카드는 같은 턴에 사용할 수 없다.
- 한 턴에 개발 카드는 1장만 사용할 수 있다.
- 승점 카드는 카드 객체 구조에서도 점수에 반영된다.

## 5. 테스트 결과

### 5.1 통과

- `node --check script.js`
  - JavaScript 문법 오류 없음
- 정적 검색
  - `newDev` 참조 제거 확인
  - `boughtTurn`, `usedDevThisTurn`, `canTakePostRollAction()`, `makeDevCard()` 확인
- 로컬 서버 HTTP 확인
  - `http://127.0.0.1:4173/` 응답 코드 200 확인
- 코드 레벨 시나리오 테스트
  - 주사위 전 도로 건설 차단
  - 주사위 전 개발 카드 구매 차단
  - 주사위 전 은행 교환 차단
  - 주사위 후 개발 카드 구매 가능
  - 개발 카드 객체에 `id`, `type`, `boughtTurn` 포함
  - 이번 턴에 산 기사 카드 사용 불가
  - 이전 턴에 산 기사 카드 사용 가능
  - 한 턴에 기사 카드 2장 사용 불가
  - 턴 종료 후 `usedDevThisTurn` 초기화
  - 승점 카드 객체 점수 계산 유지

### 5.2 수행하지 못한 테스트

- 실제 브라우저 UI 클릭 테스트

이유:

- 1단계 검증 당시 인앱 브라우저가 로컬 URL 접근을 `net::ERR_BLOCKED_BY_CLIENT`로 차단했다.
- 이번 단계는 코드 레벨 상태 전환과 함수 방어 로직 중심이므로 VM 기반 시나리오 테스트로 대체했다.

## 6. 남은 이슈

- 도로 건설, 풍년, 독점 개발 카드는 아직 구현되지 않았다.
- 승점 카드 비공개 처리는 아직 구현되지 않았다.
- 실제 브라우저에서 버튼 비활성화와 하이라이트 표시를 수동 확인하는 것이 좋다.
