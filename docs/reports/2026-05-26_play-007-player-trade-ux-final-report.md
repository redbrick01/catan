## 1. 작업 목적

플레이어 간 교환 제안 작성 중 보유량 초과 선택을 막고, 빈 제안을 차단하며, 확인 화면에서 제안을 수정할 수 있게 한다.

## 2. 변경 파일

- `script.js`
- `docs/issues/2026-05-26_playability-issues.md`
- `docs/reports/2026-05-26_play-007-player-trade-ux-final-report.md`

## 3. 수정 내용

`showPlayerTradeModal()` 내부 흐름을 작성 화면과 확인 화면으로 나눴다.

추가한 내부 함수:

- `updateProposeState()`: 제공/요청 수량이 모두 1장 이상일 때만 제안 버튼 활성화
- `refreshDraftState()`: 요약 문구와 제안 버튼 상태 동기화
- `resetRequest()`: 상대 변경 시 요청 수량 초기화
- `renderEditor()`: 교환 작성 화면 렌더링
- `renderReview(partner)`: 교환 확인 화면 렌더링

수량 제한:

- 각 자원 행의 `-` 버튼은 선택 수량이 0이면 비활성화된다.
- 각 자원 행의 `+` 버튼은 선택 수량이 해당 플레이어 보유량에 도달하면 비활성화된다.
- `+` 클릭 핸들러에서도 보유량 초과 증가를 방어한다.

제안 버튼:

- 제공 수량 합계가 0이거나 요청 수량 합계가 0이면 비활성화된다.
- 제안 직전에도 기존 자원 보유량 검증을 유지한다.

확인 화면:

- `수정`, `거절`, `수락` 버튼을 제공한다.
- `수정`을 누르면 기존 선택값을 유지한 채 작성 화면으로 돌아간다.
- `수락` 직전에도 양쪽 자원 보유량을 재검증한다.

## 4. 검증 결과

통과:

- `node --check script.js`
- 정적 검색으로 다음 변경 확인
  - `renderEditor()`
  - `renderReview(partner)`
  - `updateProposeState()`
  - `minus.disabled`
  - `plus.disabled`
  - `propose.disabled`
  - `수정` 버튼
- 브라우저에서 `http://127.0.0.1:4173/?test=1` 로드 확인
- 플레이어 교환 버튼 존재 확인
- 브라우저 콘솔 오류 없음 확인

수행하지 못한 검증:

- 실제 교환 모달에서 자원 수량을 조절하며 `+` 버튼 비활성화, 제안 버튼 활성화, 수정 화면 복귀, 수락 후 자원 이동을 클릭으로 검증

이유:

- 교환 모달은 정식 플레이 단계와 보유 자원 상태가 필요하다.
- 인앱 브라우저 평가 환경에서 `window.__catanTest` 접근이 되지 않아 필요한 상태를 빠르게 주입하지 못했다.

## 5. 남은 위험

- 수량 제한은 작성 시점의 보유량을 기준으로 한다. 확인 화면에 들어간 뒤 자원이 외부에서 변할 경우를 대비해 수락 직전 재검증을 유지했다.
- 이 작업은 로컬 모달 UX 개선이며, 원격 멀티플레이의 비동기 교환 시스템은 구현하지 않았다.
- 교환 모달 안의 상대 자원 보유량 표시는 기존 정책을 유지했다. 완전한 비공개 교환 UX는 별도 작업으로 다루는 것이 좋다.

## 6. 최종 판단

PLAY-007의 1차 수정 범위인 수량 제한, 빈 제안 차단, 수정 가능한 확인 화면, 수락 직전 재검증을 구현했고 문법 검증과 기본 브라우저 로드 검증을 통과했다.
